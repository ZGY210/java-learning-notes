## ② 代码任务详情（今天的重头戏，75 min）

你 10/26 已经读懂 `modCount` / `expectedModCount` 怎么触发 fail-fast。今天给它补上另一半：**迭代器自己的 `remove()`**。

JDK 里 `ArrayList` 的迭代器是这样的（你要对着写，不要照抄）：

```java
private class Itr implements Iterator<E> {
    int cursor;             // 下一个要返回的元素下标
    int lastRet = -1;       // 上一次返回的元素下标；-1 表示「还没返回过」
    int expectedModCount = modCount;

    public boolean hasNext() { return cursor != size; }

    public E next() {
        checkForComodification();
        int i = cursor;
        if (i >= size) throw new NoSuchElementException();
        cursor = i + 1;
        lastRet = i;
        return (E) elementData[i];
    }

    public void remove() {
        // TODO 你来填这三步：
        // 1. 如果 lastRet < 0 → throw new IllegalStateException()
        //    （next() 之前调 remove()、或连续调两次 remove()，都是非法状态）
        // 2. 先 checkForComodification()，然后调 MyArrayList.this.remove(lastRet)
        // 3. cursor = lastRet;  lastRet = -1;
        //    expectedModCount = modCount;   ← 这一行是关键！
    }
}
```

**今天必须想明白的一个问题**（写进笔记）：

> 为什么迭代器自己 `remove()` 之后，要把 `expectedModCount` 重新同步成 `modCount`？
> 答不出就先看这个场景：`for (String s : list) { if (s.equals("x")) list.remove(...); }` 会抛 ConcurrentModificationException —— 那**怎样删除才不会抛**？

（答案就是：用迭代器的 `remove()` 而不是集合的 `remove()`。而迭代器 `remove()` 之所以不抛，正是因为它在删完之后把 `expectedModCount` 同步回来了。）

**验收方法**（写进 `demo/ListTraversalDemo.java` 或单独跑）：

```java
MyArrayList<String> list = new MyArrayList<>();
list.add("a"); list.add("b"); list.add("c");
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if ("b".equals(it.next())) it.remove();   // 用迭代器删，不抛
}
System.out.println(list.size());             // 应输出 2
```

**五种遍历演示**（`demo/ListTraversalDemo.java`，用 JDK 的 ArrayList 写即可，重点是每种都要写注释说清场景）：

1. 普通 for（按下标）—— 要按下标随机访问时
2. 增强 for（for-each）—— 只读遍历
3. `Iterator` —— 需要边遍历边删除时
4. `ListIterator` —— 需要从后往前、或需要定位到上一次位置时
5. `forEach + lambda` —— 一行代码快速遍历
