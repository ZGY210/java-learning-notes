## ① 为什么把 146 放第一位

你现在手里是：`addFirst` ✅ `remove` ✅ `get` ✅ `put` ❌。

**就差最后一块。** 而 `put` 是这题真正的分水岭 —— 它要把前面三个方法串起来，还要处理三种分支：

```
put(key, value):
  1. 已经存在？ → 改 value，把节点挪到最前
  2. 不存在且没满？ → 新建节点，addFirst，存进 map
  3. 不存在且满了？ → 删掉尾节点（同时从 map 里删），新建，addFirst，存进 map
```

第 3 步有个隐蔽的坑：**删尾节点时，你必须同时从 map 里删掉那个 key**，否则 map 会越来越大、里面全是死节点。而且你得能从链表节点反推出 key —— 这就是为什么 `Node` 里要存 `key`（11/22 我问过你这个问题）。

写完 `put`，你就拥有一个完整的、自己从零写的 LRU。**这种人不多。**

## ③ TreeMapDeepen 在练什么

四个 TODO，对应四个面试题：

| TODO | 方法 | 一句话说清它证明什么 |
|---|---|---|
| 1 | `binarySearchSteps` | TreeMap 的 O(log n) 本质就是二分，16 个元素最多比 5 次、1024 个最多比 11 次 |
| 2 | `treeMapUsesCompareTo` | 3 个「equals 全等、compareTo 不同」的 key 放进 TreeMap → **size 是 3**，说明 TreeMap 根本不看 equals |
| 3 | `treeMapNullKey` | 自然排序放 null → NPE；加 `Comparator.nullsFirst` → 可以 |
| 4 | `rotateLeft` | 左旋三行指针，旋完中序不变 —— 这是红黑树维持平衡的唯一手段 |

**TODO 2 是今天最反直觉的一题**，我先说清为什么值得练：

你写 `HashMap` 的时候，去重靠 `hashCode + equals`。你顺手就会以为 TreeMap 也一样。
但其实 TreeMap 只调 `compareTo`（或 `Comparator`）。所以会出现这种事：

```java
TreeMap<EvilKey, String> map = new TreeMap<>();
// EvilKey: equals 永远 true，hashCode 恒为 1，compareTo 按 id 比
map.put(new EvilKey(1), "a");
map.put(new EvilKey(2), "b");
map.put(new EvilKey(3), "c");
map.size();   // 3 ← 同一批对象放 HashMap 只会是 1
```

面试里问「TreeMap 怎么去重」，答「equals 和 hashCode」的人当场就露了。
