## 今日四个必须能答出来的问题

1. **三种 Map 怎么选？**（HashMap / LinkedHashMap / TreeMap 各一句话）
    HashMap 要快无序（O(1)）；LinkedHashMap 要保序（插入顺序或访问顺序）；TreeMap 要排序和范围查询（O(log n) 有序）。
3. LinkedHashMap 的 `accessOrder = true` + `removeEldestEntry` 为什么就是 LRU？
    accessOrder=true 让每次 get/put 命中的节点被搬到链表尾部，于是链表头永远是最久未访问的；removeEldestEntry 每次 put 后回调，返回 size() > capacity 时自动删掉链表头，也就是淘汰最久未用。两件事合起来就是 LRU。
5. TreeMap 判断两个 key「相等」用的是什么？为什么和 HashMap 不一样？这会导致什么坑？
    用 compareTo/compare 返回 0 判定，不用 hashCode+equals。因为 TreeMap 是红黑树，靠比较关系定位节点，天然不需要哈希。坑在于：比较器返回 0 但对象其实不相等时会被当成同一 key，后 put 覆盖前一个（size 不增），数据静默丢失；反过来 equals 相等但比较器不为 0 时会被当成两个 key 共存。
7. **`hashCode` 里那个 31，为什么是 31？**
    ① 31 是奇素数，乘积碰撞概率低、散列更均匀；② 31 * i == (i << 5) - i，JVM 能优化成移位减法，比普通乘法快；③ 大小适中，太小易碰撞、太大易溢出，是实践中的平衡最优值，且 String.hashCode 等 JDK 实现也用它。
