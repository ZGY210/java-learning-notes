## ② 代码任务详情（今天的重头戏，60 min）

昨天你写了 BST。今天不用写新的树，而是**用代码把「为什么需要平衡」这件事做出来**——这是理解 AVL 和红黑树存在的唯一正确姿势。

两个 TODO，都是递归：

**TODO 1 · `height(Node node)`**：树的高度 = 最长路径的边数。

```java
// 空节点高度 -1（注意不是 0，这是 AVL 定义的标准写法）
// height(node) = max(height(left), height(right)) + 1
```

**TODO 2 · `isBalanced(Node node)`**：左右子树高度差 ≤ 1，且左右子树各自也平衡。

```java
// 空节点 → true
// |height(left) - height(right)| > 1 → false
// 否则递归判断左右子树
```

**核心实验（写在 main 里，这也是自查的内容）**：

- 平衡插入 `5,3,8,1,4,7,9` → `isBalanced` 应返回 **true**
- 顺序插入 `1,2,3,4,5` → 退化成一条链 → `isBalanced` 应返回 **false**

> 做完这个实验，你就能亲眼看到：**BST 的「平衡」不是天生的，插入顺序不对就退化成链表，查找从 O(log n) 掉到 O(n)**。这就是 AVL 要「旋转」、红黑树要「变色 + 旋转」的全部动机。

**验收**：`main` 里 6 条自查全绿（骨架已写好）。
