## ② 这个靶场在练什么

它不写任何数据结构，只做四件事：把 HashMap 内部的四个决定**算出来给你看**。

| TODO | 方法                              | 对应哪个面试题                                            |
| ---- | ------------------------------- | -------------------------------------------------- |
| 1    | `spread(int h)`                 | 为什么 hash 要 `h ^ (h >>> 16)`？（让高位也参与运算，减少碰撞）        |
| 2    | `indexOf(int hash, int cap)`    | 为什么用 `(n-1) & hash` 不用 `hash % n`？（负数不出界 + 位运算快）   |
| 3    | `bucketOf(int[] keys, int cap)` | 桶分布长什么样？（你会亲眼看到 0/16/48 全挤在一个桶里）                   |
| 4    | `rehashDiff(int[] keys)`        | 扩容时为什么只判断 `hash & oldCap`？（因为新下标只可能是 j 或 j+oldCap） |

跑完 TODO 3 你会看到这个：

```
bucketOf({0, 16, 48}, 16)  →  {0=[0, 16, 48]}     ← 三个 key 一个桶
bucketOf({0, 16, 48}, 32)  →  {0=[0], 16=[16, 48]} ← 拆成两个桶
```

这就是 214 集讲的那件事的全貌：**扩容不是重新洗牌，是把每个桶对半劈成两个**，一个留在原位，一个挪到 `原位 + oldCap`。

理解了这个，你对「为什么容量必须是 2 的幂」就有答案了 —— 因为只有 2 的幂，`(n-1)` 才是全 1 的掩码，`&` 才等价于取模，扩容才能恰好对半劈。

## 今天必须自己答出来的四句话

写进 `notes/collections/16-HashMap源码.md` 第三节。**每句不超过 50 字，说不清就是没懂**：

1. 为什么要 `h ^ (h >>> 16)`？不这么做会怎样？
    因为 indexOf 只用低位取桶，高位会被丢弃；把高 16 位异或到低位，让高位也参与运算，减少碰撞，桶分布更均匀。不做的话，高位相似的 key 会大量撞在同一桶里。
3. 为什么用 `&` 不用 `%`？举一个 `%` 会出错的例子。
     & 是位运算，比 % 快；且 (n-1) & hash 在容量为 2 的幂时等价于取模。% 在负数时结果为负（如 -5 % 16 == -5），做下标会越界，& 不会。
5. 为什么容量必须是 2 的幂？如果不是会怎样？
    只有 2 的幂，n-1 才是全 1 的掩码，& 才等价于取模、扩容才能恰好对半劈。不是 2 的幂时，n-1 有 0 位，部分桶永远取不到，分布不均且取模不等价。
7. 扩容时 `hash & oldCap` 得到 0 和得到 oldCap，分别意味着什么？
    得到 0：新下标仍是原下标，节点留在原桶；得到 oldCap：新下标 = 原下标 + oldCap，节点搬到高位桶。这正好对应“对半劈”。
