# reference/ —— 教练参考答案，不是你的成果

这个包里的三个类是**教练在你学之前就写好的参考实现**，放在这里只为了两件事：

1. 你卡住时对照**方法签名和注释**（尽量别看方法体）；
2. 写完自己的版本后，做一次 diff，看差在哪。

| 类 | 对应黑马集数 | 你要自己写在哪 |
|---|---|---|
| `MoneyUtil` | 162 BigDecimal | `api/MoneyUtil.java` |
| `RegexUtil` | 163–164 正则 | `api/RegexUtil.java` |
| `DateUtil` | 168–173 时间类 | `api/DateUtil.java` |

## 规则（写在排期表「先立三条规矩」第 ③ 条）

> **看懂的 ≠ 会写的 ≠ 面试能讲的。**

每学完一个模块，必须**关掉参考实现、从空白文件重写一遍**才算通过。判据很简单：

```powershell
git log --oneline -- api/<类名>.java
```

如果这个文件在你的学习期内**没有任何属于你的提交**，那这个模块就是没学。

## 为什么不直接放在 api/ 里

因为仓库要能拿去面试。面试官打开 `src/main/java/api/` 时，看到的必须全是**你自己写的代码**；
看到一堆明显超出你当前水平的实现，第一句话就会是「这段是你写的吗」——答不上来比不写更糟。
