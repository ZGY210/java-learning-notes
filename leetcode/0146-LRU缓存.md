## 一、题目

请你设计并实现一个满足 **LRU（最近最少使用）缓存** 约束的数据结构。

实现 `LRUCache` 类：

- `LRUCache(int capacity)` 以正整数作为容量 `capacity` 初始化 LRU 缓存
- `int get(int key)` 如果关键字 `key` 存在于缓存中，则返回关键字的值，否则返回 `-1`
- `void put(int key, int value)` 如果关键字 `key` 已经存在，则变更其数据值 `value`；如果不存在，则向缓存中插入该组 `key-value`
- 如果插入操作导致关键字数量超过 `capacity`，则应该 **逐出** 最久未使用的关键字

要求：`get` 和 `put` 必须以 **O(1)** 的平均时间复杂度运行。

---

## 二、思路（先自己想 15 分钟，再往下看）

**为什么只用一个 HashMap 不行？**

→ 因为 HashMap 拿不到「谁最久没用过」这个顺序信息。它无序。

**为什么只用一个双向链表不行？**

→ 因为链表查找是 O(n)，做不到 O(1) 的 get。

**所以：**

| 结构                 | 负责什么                      |
| ------------------ | ------------------------- |
| HashMap<key, Node> | O(1) 找到节点                 |
| 双向链表               | 维护访问顺序（头 = 最近用过，尾 = 最久没用） |

**两个关键动作（自己写的时候会反复用到）：**

1. 访问一个节点后 → 把它**摘下来，插到头部**
2. 超出容量 → **删掉尾部**那个节点（同时要记得从 map 里删）

### 你的代码

```java
import java.util.HashMap;
import java.util.Map;

class LRUCache {

    class Node {
        int key;
        int value;
        Node prev;
        Node next;
        Node(int k, int v) { this.key = k; this.value = v; }
    }

    private final int capacity;
    private final Map<Integer, Node> map;
    // 哨兵：头尾各一个，省掉大量 null 判断
    private final Node head;
    private final Node tail;

    public LRUCache(int capacity) {
        this.capacity = capacity;
        this.map = new HashMap<>();
        this.head = new Node(-1, -1);
        this.tail = new Node(-1, -1);
        head.next = tail;
        tail.prev = head;
    }

    public int get(int key) {
        Node node = map.get(key);
        if (node == null) {
            return -1;
        }
        moveToHead(node);          // 用过了 -> 提到头部
        return node.value;
    }

    public void put(int key, int value) {
        Node node = map.get(key);
        if (node != null) {
            node.value = value;    // 已存在：只改 value
            moveToHead(node);      // 并且更新访问顺序
            return;
        }
        // 不存在：新建节点插头部
        if (map.size() == capacity) {
            Node oldest = tail.prev;   // 尾哨兵的前一个就是最久未使用
            remove(oldest);
            map.remove(oldest.key);    // 必须用 node.key 去删
        }
        Node newNode = new Node(key, value);
        map.put(key, newNode);
        addFirst(newNode);
    }

    // ---------- 三个私有方法 ----------
    private void addFirst(Node node) {   // 插到 head 后面
        node.prev = head;
        node.next = head.next;
        head.next.prev = node;
        head.next = node;
    }

    private void remove(Node node) {     // 从链表摘掉
        node.prev.next = node.next;
        node.next.prev = node.prev;
    }

    private void moveToHead(Node node) { // 先 remove 再 addFirst
        remove(node);
        addFirst(node);
    }
}
```

## 四、复杂度

- 时间复杂度 ：get、put 都是 O(1)（平均）。HashMap 查找 O(1)，链表插入或摘除都是改几个指针也是 O(1)
- 空间复杂度 ：O(capacity)。HashMap 与双向链表各存最多 capacity 个节点，哨兵额外 2 个

## 五、踩坑记录（写你真实踩到的）

1. Node 里为什么必须存 key？
   
   淘汰尾节点时，需要拿它的 key 去 map.remove(key)。如果 Node 不存 key，链表中就无从得知该删 map 里的哪一项。这就是骨架注释“淘汰尾部时要用它去删 map”的含义。

2. put 一个已存在的 key 时，除了更新 value 还要做什么？
   
   还要 moveToHead(node) 更新访问顺序 —— 否则它会被当作“久未使用”提前淘汰。这里 不能 新建节点替换，否则 map 与链表的引用会脱节。

3. 为什么用“哨兵头尾”比不用好？
   
   有了 head、tail 这两个始终存在、不存真实数据的节点，addFirst、remove 就 不用判断 null 。不用哨兵的话，往空链表插、删尾节点、删头节点、删唯一节点都要分别判空，四面漏风。代价只是多两个节点。

4. 第一次提交错在哪个 case？ （这题常见坑，按典型错法写）
   
   错在 put(3,3) 淘汰那一步：淘汰时调用了 map.remove(tail.key)，而 tail 是哨兵（key = -1），结果删错 key，容量变 3，get(2) 返回 2 而不是 -1。正确写法是先 Node oldest = tail.prev;，再 map.remove(oldest.key)。
   另一种错误：put 已存在 key 时只改了 value，没有把节点移到头部，导致 get(1) 后 put(3,3) 逐出的仍是 key 1。

5. 和昨天 LinkedHashMap + removeEldestEntry 比，各自优劣？
   LinkedHashMap 版：3 行就能写出（accessOrder=true + 重写 removeEldestEntry 返回 size() > capacity），代码极短、不易出错，适合业务里用。
   手写版：能展示 哈希表 + 双向链表 这一数据结构的组合思路，是面试真正想看的；而且淘汰策略可控（比如想改 LRU/LFU 或加权重）。缺点是细节多、容易踩哨兵或删错 key 的坑。
   本质：LinkedHashMap 的 accessOrder 模式底层就是“哈希表 + 双向链表”，你手写一遍等于自己实现了一遍 LinkedHashMap 的淘汰逻辑。

## 六、自测用例（必须自己跑一遍）

| 操作                             | 期望   |
| ------------------------------ | ---- |
| `LRUCache(2)`                  | —    |
| `put(1,1)` → `put(2,2)`        | —    |
| `get(1)`                       | `1`  |
| `put(3,3)`（容量满，逐出最久未用 = key 2） | —    |
| `get(2)`                       | `-1` |
| `put(4,4)`（逐出 key 1）           | —    |
| `get(1)`                       | `-1` |
| `get(3)`                       | `3`  |
| `get(4)`                       | `4`  |

再补三个边界：容量 1 时反复 put；put 同一个 key 两次；get 一个不存在且缓存为空的 key。
