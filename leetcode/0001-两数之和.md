# 0001. 两数之和（简单）

链接：https://leetcode.cn/problems/two-sum/

---

## 一、思路

### 我自己先想到的（笨办法）

> ① 循环遍历
>
> ② 时间复杂度为O(n²)
>
> ③利用循环嵌套的方法,一个个遍历相加,与所要的值进行比较,以这个方法进行不算困难,但是代码的运行速度很慢,如果数据的复杂度提高,这个方法很难进行
> 这段别嫌丢人。面试时被问「你怎么想的」，答案就是这一段。

### 更好的做法

> 用 HashMap 把『找另一个数』从 O(n) 降到 O(1)」。

### 为什么它能成立

> 对数组里每个数 `X，它只需要跟它前面的某个人配对。 所以遍历到 `i` 时，只需在「前面所有人」里找 `target - nums[i]`，而 map 就是「前面所有人」的索引表。 任一答案对 `(i, j)`（`i < j`），在遍历到 `j` 的那一刻必然被发现——因为那时 `i 已经在 map 里了。

## 二、复杂度

| 版本  | 时间    | 空间   |
| --- | ----- | ---- |
| 笨办法 | O(n²) | O(1) |
| 更优解 | O(n)  | O(n) |

推导过程（不要只写结果）：

- **时间 O(n)**：每个元素恰好进 map 一次、被查一次；HashMap 的 `put`/`containsKey` 平均 O(1)。（JDK 8 起冲突严重会树化，最坏 O(log n)，所以严格说是**平均 O(n)**）

  **空间 O(n)**：最坏情况（答案在最后两个位置）map 里存了 n−1 个元素

## 三、代码

### 版本一：能过的（笨办法）

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        int j,i;
        for(i=0;i<nums.length;i++){
            for(j=i+1;j<nums.length;j++){
                if(nums[i]+nums[j]==target){
                    return new int[]{i,j};
                }
            }
        }
        return new int[]{0};
    }
}
```

### 版本二：更优的

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> hashtable = new HashMap<Integer, Integer>();
        for (int i = 0; i < nums.length; ++i) {
            if (hashtable.containsKey(target - nums[i])) {
                return new int[]{hashtable.get(target - nums[i]), i};
            }
            hashtable.put(nums[i], i);
        }
        return new int[0];
    }
}
```

## 四、踩坑

> 这一栏是四段里**最值钱**的。面试官问「你踩过什么坑」时，答案从这里来。

- [ ] 坑 1: 错法: put 写在 containsKey   结果: 如 [3,3] , target=6 --> 返回 [0,0]
- [ ] 坑 2: 错法: 先全存进 map 再遍历查找  结果: 如 [3,2,4] , target=6 --> 返回 [0,0]
- [ ] 坑 3: 错法: 查containsKey(nums[i])而不是target-nums[i]  结果: 永远匹配自己，全错
- [ ] 坑 4: 错法: 返回写成[i,map.get(neet)]  结果: 下标顺序反了
- [ ] 坑 5: 错法: 兜底返回new int[]{0}  结果: 题面保证有解,{0}会让人误以为「下标 0」是答案，写new int[0]
