# 0015. 三数之和（中等）

> 阶段一第 5 题（排序 + 双指针判重，超高频）。先想 40 分钟，别急着看题解。
> 提示：你可以先排序，再用「固定一个 + 对撞双指针找另外两个」的思路。

链接：https://leetcode.cn/problems/3sum/

## 一、思路

### 我自己先想到的（笨办法）

> ① **第一反应** ：直接写三层嵌套循环，枚举所有三元组 `(i,j,k)`，判断 `nums[i] + nums[j] + nums[k] == 0`，最后再用集合去重。
>
> ② **复杂度** ：时间 O(n³)，空间 O(n)（用来存结果去重）。
>
> ③ **卡在哪里、为什么不够好** ：三层循环在 n 稍大时直接超时，而且手动去重非常笨重，会产生大量重复三元组，完全没有利用"排序后可以用双指针快速缩小范围"的特性。本质是我只想着暴力枚举所有组合，没意识到排序后问题可以大幅简化。

### 更好的做法

> **悟点** ：先把数组排序，然后固定第一个数，剩下两个数用左右双指针从两端往中间夹，把"找两数之和等于 -nums[i]"的过程从 O(n²) 降到 O(n)，同时在遍历过程中主动跳过重复元素，天然避免重复三元组。
>
> 一句话： **排序 + 固定一个数 + 对撞双指针，把 O(n³) 暴力降成 O(n²)。**

### 为什么它能成立

> - 排序后数组有序，双指针移动有明确方向：三数和小于 0 就左指针右移（变大），大于 0 就右指针左移（变小），不会漏掉任何一组解。
> - 固定第一个数时，只要发现和上一个数相等就直接跳过，天然避免第一个数重复；左右指针找到解后，也各自跳过相邻的重复元素，从源头杜绝重复三元组。
> - 排序后，所有满足条件的三元组都会被有序地枚举出来，不会出现乱序导致的重复统计，也不需要额外开集合去重。

## 二、复杂度

| 版本  | 时间    | 空间   |
| --- | ----- | ---- |
| 笨办法 | O(n³) | O(n) |
| 更优解 | O(n²) | O(1) |

推导过程（不要只写结果）：

- **时间** ：排序是 O(n log n)；外层固定第一个数循环跑 n 次，内层双指针总共从两端走到中间，每一轮双指针遍历是 O(n)，整体是 O(n²)。O(n²) 远大于 O(n log n)，最终时间复杂度由双指针部分主导，为 **O(n²)** 。
- **空间** ：只用到了 i、left、right 几个下标变量，排序如果是原地排序（比如 Java Arrays.sort 双轴快排），不需要额外开数组，额外空间是常数级，为 **O(1)** 。结果列表本身不算算法额外开销。

## 三、代码

### 版本一：能过的（笨办法）

```java
// 暴力三重循环 + Set 去重，能过但 n 稍大就超时
public List<List<Integer>> threeSumBrute(int[] nums) {
    Set<List<Integer>> set = new HashSet<>();
    Arrays.sort(nums); // 先排序，保证三元组顺序一致，方便 Set 去重
    int n = nums.length;
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            for (int k = j + 1; k < n; k++) {
                if (nums[i] + nums[j] + nums[k] == 0) {
                    set.add(Arrays.asList(nums[i], nums[j], nums[k]));
                }
            }
        }
    }
    return new ArrayList<>(set);
}

```

### 版本二：更优的

```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> res = new ArrayList<>();
        Arrays.sort(nums);
        int n = nums.length;
        for (int i = 0; i < n - 2; i++) {
            // 剪枝：第一个数已经大于0，后面全正，不可能凑出和为0
            if (nums[i] > 0) break;
            // 跳过重复的第一个数
            if (i > 0 && nums[i] == nums[i - 1]) continue;
            
            int left = i + 1, right = n - 1;
            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];
                if (sum < 0) {
                    left++;
                } else if (sum > 0) {
                    right--;
                } else {
                    res.add(Arrays.asList(nums[i], nums[left], nums[right]));
                    // 跳过左指针相邻重复
                    while (left < right && nums[left] == nums[left + 1]) left++;
                    // 跳过右指针相邻重复
                    while (left < right && nums[right] == nums[right - 1]) right--;
                    // 同时推进两个指针
                    left++;
                    right--;
                }
            }
        }
        return res;
    }
}
 }
    }
    return res;
}

```

## 四、踩坑

> 这一栏是最值钱的。面试官问「你踩过什么坑」时，答案从这里来。

- [ ] 坑 1：写成了 **没排序直接跑双指针** ，结果是 **完全找不到正确解，指针移动方向毫无依据** ，原因是 **对撞双指针的前提是数组有序，无序数组里你根本不知道该往左还是往右走** 。
- [ ] 坑 2：写成了 **只在 i 层去重，left 和 right 找到解后没跳过相邻重复元素** ，结果是 **输出大量重复三元组，比如 [-1,0,1] 反复出现多次** ，原因是 **只防了第一个数重复，没防后两个数重复，重复组合还是会被统计出来** 。
- [ ] 坑 3：写成了 **去重判断写反，用 `nums[i] == nums[i+1]` 跳过** ，结果是 **直接把合法的第一个解给跳过去了，漏掉正确答案** ，原因是 **应该和上一个已经处理过的元素比，不是和下一个还没处理的元素比** 。
- [ ] 坑 4：写成了 **没加 `nums[i] > 0 break` 剪枝** ，结果是 **数组全正数之后还在空跑循环，白白浪费大量无效遍历** ，原因是 **排序后第一个数已经大于0，后面所有数都比它大，三个正数相加不可能等于0** 。
- [ ] 坑 5：写成了 **找到解之后只 left++ 或者只 right--，不同时移动两个指针** ，结果是 **死循环卡在原地，sum 永远等于0** ，原因是 **三个数都没变，和永远是0，指针永远不会推进** 。
- [ ] 坑 6：写成了 **暴力三重循环不加排序直接丢进 Set** ，结果是 **同一个三元组以不同顺序被当成不同元素，Set 根本去不掉重** ，原因是 **List 的 equals 是按顺序比较的，不排序的话 [-1,0,1] 和 [0,-1,1] 会被判定成两个不同对象** 。
