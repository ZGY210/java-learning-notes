## 一、思路

### 我自己先想到的（笨办法）

> **第一反应** ：能不能用 BFS 层序遍历？拿个队列一层一层剥，剥一层计数加一，队列空了就得到深度。
>
> **复杂度** ：时间 O(n)（每个节点进出队列一次），空间 O(最宽一层的节点数)，最坏 O(n)。
>
> **为什么不够好** ：思路本身是对的，但代码量大——要手写队列、内层 for 循环控制「当前层有多少个节点」。而这道题的核心考点是 **递归定义** ，用 BFS 答等于绕开考点。面试官想听的是「一棵树的深度 = 左右子树深度的最大值 + 1」这句话。

### 更好的做法（递归）

> **顿悟点** ： **别去模拟「怎么一层层数下去」，而是相信「子问题能自己算出来」。**

**提示**：一棵树的最大深度 = `max(左子树的最大深度, 右子树的最大深度) + 1`。空树深度是 0。这就是完整的递归定义。

### 为什么它能成立

> **每次递归都在「变小」** ——往子树走，问题规模减去当前这一层，直到走到叶子节点（左右都空）。此时两个子树的深度都是 0（因为空树深度是 0），`max(0, 0) + 1 = 1`，正确返回。 **规模严格递减 + 有明确终止条件（node == null）** ，所以必然收敛，不会死循环。

**提示**：每次递归都在「变小」——往子树走，深度减 1。到叶子节点（左右都空）时，两个子树深度都是 0，返回 1。有明确的终止条件。

## 二、复杂度

| 版本  | 时间   | 空间                       |
| --- | ---- | ------------------------ |
| 递归  | O(n) | O(h)，最坏 O(n)，平均 O(log n) |

要只写结果）：

- 时间：每个节点恰好被访问一次，做常数次比较和加法，T(n) = T(left) + T(right) + O(1) → O(n)。
- 空间：递归不显式开数组，但 **递归调用栈** 的深度等于树高 h。链状树 h = n → 最坏 O(n)；平衡树 h = log n → 平均 O(log n)。

## 三、代码

### 递归版

```java
class Solution {
    public int maxDepth(TreeNode root) {
        if (root == null) return 0;
        return Math.max(maxDepth(root.left), maxDepth(root.right)) + 1;
    }
}
```

### BFS 版（可选，用队列按层遍历）

> 层序遍历也能求深度：每扫完一层，深度 +1。写得出就写，写不出标「还没想明白」。

## 四、踩坑

> 这一栏是四段里**最值钱**的。

- [ ] 坑 1：空树返回了 1 而不是 0（空树深度是 0）。
    根因：把「节点数」和「深度」搞混。空树一个节点都没有，深度当然是 0，if (root == null) return 0; 不能省。
- [ ] 坑 2：忘了 `+1`，只返回了子树深度（当前节点自己也算一层）。
    根因：递归式写成了 Math.max(maxDepth(left), maxDepth(right))，漏掉根节点贡献的那一层。叶子节点会返回 0 而不是 1。
- [ ] 坑 3：把「深度」和「节点个数」混了（单节点树深度是 1，节点数是 1，容易混）。
    这类题里两者恰好都等于 1，容易蒙混过关；但换成 [1,2] 就露馅了：深度 2，节点数 2；[1,2,3] 深度 2，节点数 3。 用这个例子自测能立刻分辨。
