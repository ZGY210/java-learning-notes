## 一、思路

### 我自己先想到的（笨办法）

> ① 第一反应：把链表的值全部取出来放进数组，倒序后再写回节点。  
> ② 复杂度：遍历两次，时间 O(n)，额外需要一个长度为 n 的数组，空间 O(n)。  
> ③ 卡在哪里：值可以倒着写，但节点的 next 指针还是原方向 —— 这只能"改值"，不能真正"改指向"。如果节点还被人持有引用（题目之外的情况）就会出问题；本质上是没理解"反转"要动的是指针而不是数据。

### 更好的做法（迭代：三指针）

> 顿悟点：链表反转没有"就地移动"的办法，只能一个个把 next 调头，而调头会丢失后半段，所以必须在调头前先把 next 存起来 —— 于是自然就有 prev / cur / next 三个变量。

**提示**：反转的本质是「把每个节点的 next 掉头」。掉头前必须先把原来的 next 记下来，否则链就断了。三个变量：`prev`（已经反转好的部分）、`cur`（当前要掉头的节点）、`next`（还没动的部分）。

### 为什么它能成立

> 每个节点只被处理一次 next 调头，n 个节点就是 n 次操作，O(n)；全程只用了三个指针变量，O(1)。循环结束时 cur == null，此时 prev 恰好指向原链表的最后一个节点，也就是新链表的头，直接返回 prev。

**提示**：每个节点只做一次「next 掉头」，n 个节点就是 n 次操作，O(n)。空间只需要三个指针，O(1)。

### 进阶：递归版

> 先递归反转 head.next 之后的整段链表，得到新的头 newHead；此时 head.next 已经是原链表的最后一个节点，把它的 next 指回 head，再让 head.next 置空。

## 二、复杂度

| 版本  | 时间   | 空间   |
| --- | ---- | ---- |
| 迭代  | O(n) | O(1) |
| 递归  | O(n) | O(n) |

推导过程（不要只写结果）：

- 迭代：n 个节点，每个节点做固定次数的指针赋值（存 next、改 next、推进 prev/cur），操作数正比于 n，所以时间 O(n)；只用 prev/cur/next 三个变量，与输入规模无关，空间 O(1)。
- 递归：每层做 O(1) 的指针操作，共 n 层，时间 O(n)；递归调用栈深度为 n，所以空间 O(n)。

## 三、代码

### 版本一：迭代

```java
class Solution {
    public ListNode reverseList(ListNode head) {
        // 三指针: prev / cur / next
        ListNode prev = null;
        ListNode cur = head;

        while (cur != null) {
            ListNode next = cur.next; // ① 先记下还没动的部分
            cur.next = prev;          // ② 掉头
            prev = cur;               // ③ prev 前进
            cur = next;               // ④ cur 前进
        }
        return prev;                  // 循环结束时 cur == null，prev 是新头
    }
}

```

## 四、踩坑

> 这一栏是四段里**最值钱**的。

- [x] 坑 1：先改了 `cur.next` 再去拿 `cur.next` —— 链已经断了。顺序必须是「先记 next，再掉头」。
- [x] 坑 2：循环结束后返回了 `cur` 而不是 `prev` —— `cur` 最后是 null，`prev` 才是新的头。
- [x] 坑 3：忘记处理空链表 / 单节点链表。
