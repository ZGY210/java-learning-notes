## 一、思路

### 我自己先想到的（笨办法）

> ① **第一反应** ：暴力枚举所有两根柱子的组合，算 `min(h[i], h[j]) × (j - i)` 取最大值。
>
> ② **复杂度** ：两两组合共 C(n,2) ≈ n²/2 种， **时间复杂度 O(n²)** ，空间 O(1)。
>
> ③ **卡在哪 / 为什么不够好** ：n = 10⁵ 时，n² = 10¹⁰ 次运算， **必然超时** （一般 10⁸ 量级就是上限）。问题是重复计算太多，没有利用"宽度递减"这个结构。

### 更好的做法

> **关键的顿悟点** ： **面积 = min(高) × 宽** 。左右各指一头时宽度最大；如果移动 **较长** 的那根，宽度变小、而高度受短边限制不会变大，面积只会更小。所以 **每次只能移动较短的那一边** 。

### 为什么它能成立

> 要证明" **移动较短的一边不会漏掉最优解** "。
>
> 反证：假设最优解包含当前这根 **较短** 的柱子，那么它跟任何另一根柱子配对， **高度都被这根短板限制住了** ；而当前宽度已经是这些配对里 **最大** 的。也就是说，这根短板的所有可能配对里，当前就是它的 **最好情况** ——已经考察过了，不需要再留着它。所以放心往内移动短

## 二、复杂度

| 版本  | 时间    | 空间   |
| --- | ----- | ---- |
| 笨办法 | O(n²) | O(1) |
| 更优解 | O(n)  | O(1) |

推导过程（不要只写结果）：

- 时间：

  **笨办法** ：两层循环枚举所有柱子组合。外层 i 走 n 次，内层 j 从 i+1 到 n-1 走约 n-i 次，总次数 = C(n,2) = n(n-1)/2 ≈ **n²/2** 。去掉常数系数，即 **O(n²)** 。

  **更优解（双指针）** ：left 从 0 往右、right 从 n-1 往左，每轮循环 **必有一边移动一格** ，两个指针合计最多走 n 步，所以循环执行 **最多 n 次** 。每轮内部只做常数次比较和计算，故总时间为 **O(n)** 。
- 空间：

  **笨办法** ：只用 i、j、max、area 等固定几个变量，不随 n 增长 → **O(1)** 。

  **更优解** ：只用 left、right、max、h、area 等固定几个变量，同样不随 n 增长 → **O(1)** 。

## 三、代码

### 版本一：能过的（笨办法）

```java
public int maxArea(int[] height) {
    int n = height.length;
    int max = 0;
    // 枚举所有两根柱子的组合
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            int h = Math.min(height[i], height[j]); // 高度取短板
            int area = h * (j - i);                 // 宽度 = 下标差
            if (area > max) {
                max = area;
            }
        }
    }
    return max;
}

```

### 版本二：更优的

```java
public int maxArea(int[] height) {
    int left = 0, right = height.length - 1;
    int max = 0;
    while (left < right) {
        int h = Math.min(height[left], height[right]);
        int area = h * (right - left);
        max = Math.max(max, area);
        // 谁短移动谁
        if (height[left] < height[right]) {
            left++;
        } else {
            right--;
        }
    }
    return max;
}

```

## 四、踩坑

> 这一栏是四段里**最值钱**的。

- [x] 坑 1：面积用了 `Math.max` 而不是 `Math.min` —— 水的高度取决于**短**的那块板。
- [x] 坑 2：`(right - left)` 写成了 `(right - left + 1)`，宽度是下标差，不是元素个数。
- [x] 坑 3：移动指针时移动了较长的那边 —— 想清楚为什么错。
