## 一、思路

### 我自己先想到的（笨办法）

> 写清楚：① 我的第一反应是什么 ② 它的复杂度是多少 ③ 卡在哪里、为什么不够好。

**提示**：最容易错的思路是「只比较当前节点和它的左右孩子」。为什么不够？—— BST 要求的是「**整棵**左子树 < 根 < **整棵**右子树」，不是「左孩子 < 根 < 右孩子」。

### 更好的做法（两种）

**做法 A · 中序遍历递增**：BST 的中序遍历天然升序（你昨天刚写过）。所以只要中序遍历一遍，检查每个值都比前一个大。

**做法 B · 上下界递归**：每个节点带着一个合法范围 `(min, max)`。根的范围是 `(-∞, +∞)`；左孩子范围变成 `(min, root.val)`；右孩子范围变成 `(root.val, max)`。任何一个节点越界就是非法。

### 为什么它能成立

> 为什么「上下界递归」是对的？

**提示**：BST 的定义本身就是递归的——「左子树所有值 < 根 < 右子树所有值」。「所有值」怎么一次性保证？就是给每个子树传一个取值范围。这样每个节点只需检查自己是否在范围内，而不必回看祖先。

## 四、踩坑

> 这一栏是四段里**最值钱**的。

- [ ] 坑 1：只比较当前节点和左右孩子，漏了「整棵子树」的约束（经典错解）。
- [ ] 坑 2：用 int 记录「上一个值」导致溢出 / 边界错误，应该用 long 或 null。
- [ ] 坑 3：边界用闭区间 `[min, max]` 写成了开区间 `(min, max)`——BST 不允许相等值，所以是**开区间**。
