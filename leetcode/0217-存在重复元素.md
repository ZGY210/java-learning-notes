# 0217. 存在重复元素（简单）

> 清单第 18 题 ｜ 写于 2026-11-04 ｜ 和今天视频主题（HashSet）直接对应
> 这题的价值不在「做出来」，而在**用两种完全不同复杂度的思路做出来，并讲清为什么差这么多**。

链接：https://leetcode.cn/problems/contains-duplicate/

**题目**：给你一个整数数组 `nums`。如果任一值在数组中出现**至少两次**，返回 `true`；如果数组中每个元素互不相同，返回 `false`。

示例：

- `nums = [1,2,3,1]` → `true`
- `nums = [1,2,3,4]` → `false`
- `nums = [1,1,1,3,3,4,3,2,4,2]` → `true`

---

## 一、思路

### 我自己先想到的（笨办法）

> - 双层 for：最简单直观，但每个元素都要和后面所有元素比，n 个元素就是 n² 量级，数据一大就废。
> - 排序 + 相邻比较：排完序后，相等的数一定挨在一起，扫一遍就能发现。但要先付出排序的代价，而且会意外改动原数组（除非先拷贝，又多 O(n) 空间）。

### 更好的做法

> 题目的本质是判断「这个数之前出现过没有」。
>
> - 数组的线性查找是 O(n)，每次判断都要从头扫，整体退化成 O(n²)。
> - HashSet 的 `contains` / `add` 平均是 O(1)，每个元素只处理一次，整体就降到 O(n)。
>
> 笔记里那个细节要落实： **`Set.add()` 本身就返回 boolean** ，返回 `false` 意思是「这个值已经存在，加失败」，也就是「出现过」。
>
> 这样就 **省掉了一次 `contains` 调用** ——本来要「先 contains 判断、再 add」，现在 add 一次就拿到答案。

### 为什么它能成立

> - `HashSet` 底层是 `HashMap`，先用 `hashCode` 算出桶下标，O(1) 定位；
> - 再用 `equals` 在桶内判等；
> - 元素均匀分散时，每个桶里平均只有常数个元素，所以单次操作平均 O(1)；
> - 最坏情况：所有元素哈希全撞一个桶，桶内退化成链表（或红黑树），单次退化成 O(n)，整体 O(n²)。所以严格说是「 **平均 O(n)、最坏 O(n²)** 」。

## 二、复杂度

| 版本           | 时间               | 空间                      |
| ------------ | ---------------- | ----------------------- |
| 笨办法（两层 for）  | O(n²)            | O(1)                    |
| 笨办法（排序后相邻比较） | O(n log n)       | O(1)（原地排序）/ O(n)（拷贝后排序） |
| 更优解（HashSet） | 平均 O(n)，最坏 O(n²) | O(n)                    |

推导过程（不要只写结果）：

- **双层 for 时间** ：外层 n 次，内层平均 n/2 次，比较次数 ≈ n²/2，去掉常数就是 O(n²)。空间没有额外数组，O(1)。
- **排序时间** ：`Arrays.sort(int[])` 用的是双轴快排，平均 O(n log n)（对象数组走 TimSort 也是 O(n log n)）；扫一遍相邻 O(n)，取大者即 O(n log n)。若是原地排序空间 O(log n) 递归栈，算作 O(1) 级别；拷贝一份则是 O(n)。
- **HashSet 时间** ：n 个元素，每个 add 平均 O(1)，共 O(n)。空间：最多存下 n 个不同元素，O(n)。

  一句话对比： **O(n²) → O(n log n) → O(n)**

## 三、代码

### 版本一：能过的（笨办法）

```java
class Solution {
    public boolean containsDuplicate(int[] nums) {
        Arrays.sort(nums);
        for (int i = 1; i < nums.length; i++) {
            if (nums[i] == nums[i - 1]) {
                return true;
            }
        }
        return false;    }
}

```

### 版本二：更优的（HashSet）

```java
class Solution {
    public boolean containsDuplicate(int[] nums) {
        Set<Integer> set = new HashSet<>();
        for (int num : nums) {
            if (!set.add(num)) {   // 加失败 → 说明已存在 → 重复
                return true;
            }
        }
        return false;
    }
}

```

> 提示：`Arrays.stream(nums).distinct().count() != nums.length`

## 四、踩坑

> 这一栏是四段里最值钱的。

- [ ] 坑 1：版本二写成「先 contains 再 add」
    结果是能过，但每个元素要做两次哈希定位（contains 一次、add 一次）。题目特意要求「靠 add 返回值判断」，就是为了让你意识到 add 自带判重信息， 一次操作拿两个信息 。
- [ ] **坑 2：版本一排序后忘了先判断长度或者直接改原数组**

      排序会原地修改传入的 nums。如果调用方后续还要用原数组，就出 bug。要么提前 clone()，要么用 Arrays.copyOf（代价是多 O(n) 空间）。
- [ ] 坑 3（必写）：这题如果要求**返回重复的那个数字本身**而不是 true/false，代码要怎么改？面试常这么追问。
    思路是一样的，只是把「返回 true」换成「返回这个数」；并且要注意 可能有多个重复数 ，题目没说返回哪个，通常返回任意一个或者第一个遇到的。
    面试追问往往还会继续：「如果有多个重复数，只返回一个还是全部？」——全部的话就把重复的放进一个 List 返回，逻辑还是「add 失败就收集」。
