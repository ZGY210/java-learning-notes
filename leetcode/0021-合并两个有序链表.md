# 0021. 合并两个有序链表（简单）

> 链表第 2 题。**虚拟头节点（dummy）套路**的第一课，之后很多链表题都靠它。
> 填不出来的段落不要删，写「还没想明白：……」比留空有用。

链接：https://leetcode.cn/problems/merge-two-sorted-lists/

## 一、思路

### 我自己先想到的（笨办法）

> 写清楚：① 我的第一反应是什么 ② 它的复杂度是多少 ③ 卡在哪里、为什么不够好。

### 更好的做法（虚拟头节点）

> 关键的那个「顿悟点」是什么？

**提示**：两个链表都已经有序。每次比较两个链表的头，把小的接到结果尾部，然后小的那个链表往前走一步。重复直到一个链表空了，把另一个整个接上。

「虚拟头节点」解决什么问题？—— 结果链表的第一个节点还不知道是谁，用一个假节点 `dummy` 占位，最后返回 `dummy.next`，就不用特判「空结果」。

### 为什么它能成立

> 为什么每次只比较两个链表的头就够了？

**提示**：因为两个链表各自有序，两个「当前头」里较小的那个，一定是「剩下的所有节点」里最小的。贪心正确。

## 三、代码

### 迭代版（dummy 头节点）

```java
class Solution {
    public ListNode mergeTwoLists(ListNode l1, ListNode l2) {
        // dummy 套路：
        // ListNode dummy = new ListNode(-1);
        // ListNode cur = dummy;
        // while (l1 != null && l2 != null) { 小的接到 cur.next，对应链表前进 }
        // cur.next = (l1 != null) ? l1 : l2;  接上剩余

    }

```

### 递归版（可选）

> 递归思路一句话：`merge(l1, l2)` = 较小的头的 next 指向 `merge(剩下的, 另一个)`。写得出就写，写不出标「还没想明白」。

## 四、踩坑

> 这一栏是四段里**最值钱**的。

- [ ] 坑 1：忘记在循环结束后接上剩余的那个链表（`cur.next = l1 != null ? l1 : l2`）。
- [ ] 坑 2：返回了 `cur` 而不是 `dummy.next` —— `cur` 已经走到末尾了。
- [ ] 坑 3：`dummy` 直接 `new ListNode(0)` 就返回，没注意 `dummy.next` 才是真头。
