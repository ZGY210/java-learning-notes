# 0021. 合并两个有序链表（简单）

> 链表第 2 题。**虚拟头节点（dummy）套路**的第一课，之后很多链表题都靠它。
> 填不出来的段落不要删，写「还没想明白：……」比留空有用。

链接：https://leetcode.cn/problems/merge-two-sorted-lists/

---

## 一、思路

### 我自己先想到的（笨办法）

> - **第一反应** ：把两个链表的节点值全部取出来放进一个数组，排序后再按顺序新建节点串成一条链表。
> - **复杂度** ：设两个链表长度分别为 n、m。收集 O(n+m)，排序 O((n+m)log(n+m))，重建 O(n+m)，总时间 O((n+m)log(n+m))，空间 O(n+m)。
> - **卡在哪里、为什么不够好** ：完全浪费了「两个链表本身已经有序」这个条件，还额外开了 O(n+m) 的空间新建节点；如果题目要求「复用原节点、不新建」，这个写法就直接不成立。

### 更好的做法（虚拟头节点）

> 两个链表都已经有序，所以每次只要看两个链表的头，把较小的那个摘下来接到结果链表尾部，被摘的那条链往前移一步——不需要任何排序，一趟线性扫描就能串好。

**提示**：两个链表都已经有序。每次比较两个链表的头，把小的接到结果尾部，然后小的那个链表往前走一步。重复直到一个链表空了，把另一个整个接上。

「虚拟头节点」解决什么问题？—— 结果链表的第一个节点还不知道是谁，用一个假节点 `dummy` 占位，最后返回 `dummy.next`，就不用特判「空结果」。

### 为什么它能成立

> 因为两个链表各自有序，两个「当前头」里较小的那个，一定是「剩下的所有节点」里最小的。所以每次把它接到尾部都不会破坏整体有序 —— **贪心正确** 。

**提示**：因为两个链表各自有序，两个「当前头」里较小的那个，一定是「剩下的所有节点」里最小的。贪心正确。

## 二、复杂度

| 版本  | 时间     | 空间   |
| --- | ------ | ---- |
| 迭代  | O(m+n) | O(1) |

推导过程（不要只写结果）：

- **时间** ：每个节点只被访问一次，共 n+m 个节点，所以是 O(n+m)。
- **空间** ：只新建了 `dummy` 和几个指针，与输入规模无关，O(1)。

## 三、代码

### 迭代版（dummy 头节点）

```java
class Solution {
    public ListNode mergeTwoLists(ListNode l1, ListNode l2) {
        // dummy 套路：
        ListNode dummy = new ListNode(-1);
        ListNode cur = dummy;
        while (l1 != null && l2 != null) {
            if (l1.val <= l2.val) {
                cur.next = l1;
                l1 = l1.next;
            } else {
                cur.next = l2;
                l2 = l2.next;
            }
            cur = cur.next;
        }
        // 一个链表空了，把另一个整个接上
        cur.next = (l1 != null) ? l1 : l2;
        return dummy.next;
    }
}
```

### 递归版（可选）

> 递归思路一句话：`merge(l1, l2)` = 较小的头的 next 指向 `merge(剩下的, 另一个)`。写得出就写，写不出标「还没想明白」。

## 四、踩坑

> 这一栏是四段里**最值钱**的。

- [ ] 坑 1：忘记在循环结束后接上剩余的那个链表（`cur.next = l1 != null ? l1 : l2`）。
- [ ] 坑 2：返回了 `cur` 而不是 `dummy.next` —— `cur` 已经走到末尾了。
- [ ] 坑 3：`dummy` 直接 `new ListNode(0)` 就返回，没注意 `dummy.next` 才是真头。
