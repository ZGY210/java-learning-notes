# 0024. 两两交换链表中的节点（中等）

> 链表第 5 题。虚拟头 + 三指针的经典题，面试常考。

## 一、思路

### 我自己先想到的（笨办法）

> **① 第一反应** ：想直接改 `head` 和 `head.next` 两个节点的指针，但只拿一个 `head` 引用，改完 `head.next` 后就找不到"第二个节点"了，卡在"交换后谁来指回第一个节点"。
>
> **② 复杂度** ：如果靠新建节点复制值再拼，时间 O(n)、空间 O(n)；但其实这题不该新建节点，应该原地改指针，空间可以做到 O(1)。
>
> **③ 卡在哪、为什么不够好** ：卡在 **头节点会变** ——交换后原来的 `head` 变成第二个，需要单独特殊处理头；而且单链表没有 `prev` 指针，改完 `a.next` 就失去了"谁指向 b"的信息，必须有第三个指针记住前驱。所以笨办法要么写一堆头节点特判，要么额外建节点，都不够干净。

### 更好的做法（dummy + 三指针）

> **关键的"顿悟点"** ：两两交换不是"反转头节点"，而是 **"把后面两个节点反过来接"** ——每一组都是"前驱 pre + 第一个 a + 第二个 b"的局部重连，前驱 pre 负责把它接回链表。
>
> **为什么没有它就不行** ：单链表只有 `next`，改完 `a.next`、`b.next` 后，"谁指向 b"这个问题只能由 b 的前一个节点（pre）回答。加 dummy 让第一组也拥有了 pre（即 dummy），这样 **所有组都有前驱，代码不需要任何头节点特判** 。

**提示**：两两交换的本质是「把后面两个节点反过来接」。为了避免处理头节点特判，用 dummy 虚拟头。三个指针：`pre`（要交换的两个节点的前一个）、`a`（第一个）、`b`（第二个）。

交换三步：

```
pre.next = b;
a.next = b.next;
b.next = a;
pre = a;   // 下一轮的 pre 是当前轮的 a
```

### 为什么它能成立

> 交换只是改三个指针，不新增/删除任何节点，所以链表的节点集合不变，只是顺序变了。每一组三指针的赋值顺序（先 `pre.next=b`、再 `a.next=b.next`、最后 `b.next=a`）保证： **先接住后面那段（b.next 记在 a.next 里），再重连 b** ，任何时候都不会丢失剩余链表。

**提示**：单链表只有 next 指针，改 a.next 和 b.next 后，谁来指向 b？必须靠 b 的前一个节点（pre）。这就是 dummy + 三指针的意义。

## 二、复杂度

| 版本  | 时间   | 空间   |
| --- | ---- | ---- |
| 迭代  | O(n) | O(1) |
| 递归  | O(n) | O(n) |

推导过程（不要只写结果）：

- **时间** ：`while` 循环每次处理一对节点（2 个），消耗 O(1) 时间；n 个节点共 n/2 次循环，总访问每个节点一次 → **O(n)** 。
- **空间** ：迭代只用 `dummy`、`pre`、`a`、`b` 四个引用变量，与 n 无关 → **O(1)** ；递归每层调用栈占用一帧，共下潜 n/2 层 → **O(n)** （严格说是 O(⌈n/2⌉)）。

## 三、代码

### 迭代版（dummy + 三指针）

```java
class Solution {
    public ListNode swapPairs(ListNode head) {
        ListNode dummy = new ListNode(0, head);
        ListNode pre = dummy;   // pre 指向「待交换两节点的前一个」

        while (pre.next != null && pre.next.next != null) {
            ListNode a = pre.next;       // 第一个
            ListNode b = a.next;         // 第二个

            // 交换三步
            pre.next = b;                // ① 前驱接到新头（b）
            a.next = b.next;             // ② 第一个接到 b 后面那段（必须在这之前先拿到 b.next）
            b.next = a;                  // ③ 第二个指回第一个

            pre = a;                     // ④ 下一轮的 pre 是当前轮的 a（它现在是这一组尾巴）
        }
        return dummy.next;
    }
}

```

### 递归版（可选）

> 递归思路：`swapPairs(head)` = 把 head 和 head.next 交换，然后 head.next = swapPairs(剩下的)。写得出就写，写不出标「还没想明白」。

## 四、踩坑

> 这一栏是四段里**最值钱**的。

- [ ] 坑 1：交换三步的顺序写乱（先改哪个指针会断链？）。
    我踩了 。一开始写成 b.next = a; a.next = b.next;——顺序反了。b.next=a 先执行，把 b 原本的后继（第 3 个节点）覆盖成 a，接着 a.next=b.next 取到的是 a 自己，于是 a → a → a 成环，输出超时/死循环。
    教训 ：凡是"要读 x.next"的赋值，必须排在"写 x.next"的赋值 之前 。口诀： 先读后写，先接后退 。
- [ ] 坑 2：`while` 条件只写了 `pre.next != null`，漏了 `pre.next.next != null`（奇数长度时 NPE）。
    我踩了 。只判 pre.next != null，当剩下最后 1 个节点（奇数长度）时，循环还进得去，b = a.next 拿到 null，紧接着 b.next 一波操作就 NPE。
    教训 ：循环体里要访问 pre.next.next，条件就必须两个都判，且 顺序不能反 （先 pre.next，短路才能安全再取 pre.next.next）。
- [ ] 坑 3：最后忘了 `pre = a`，导致下一轮还是处理同一对。
    我踩了 （第一版漏写）。漏了之后 pre 永远停在 dummy，第二次循环又把 dummy.next 那一对重排了一遍，而后面那段没动，最后直接把后面的链丢了——[1,2,3,4] 测出来是 [2,1]。
    教训 ：pre = a 而不是 pre = b。因为交换后 a 才是这一组的尾巴，b 是这一组的头，用 b 会把下一轮的窗口错开一格。
