# LeetCode 41 · 缺失的第一个正数

> 日期：2026-11-16 ｜ 难度：困难 ｜ 标签：数组、原地哈希
> 思考上限 **30 分钟**。要求：时间 `O(n)`、空间 `O(1)`。**不许排序，不许用哈希表。**
> 这是双列开局前最后一道数组题，考的是「把下标当哈希键」这个思维。

**题目**：给你一个未排序的整数数组 `nums`，找出其中没有出现的最小的正整数。

```
输入：[1,2,0]     输出：3
输入：[3,4,-1,1]  输出：2
输入：[7,8,9,11,12] 输出：1
```

---

## 一、先想清楚答案的范围（这一步想通了，题就一半了）

数组长度是 `n`。**为什么答案一定在 `[1, n+1]` 之间？**

因为：要装下 `1, 2, ..., n+1` 这 `n+1` 个正数，至少需要 `n+1` 个位置，而我们只有 `n` 个。
所以「前 n 个连续正整数都出现了」是不可能的 —— 必然缺一个，缺的那个 ≤ `n+1`。

- 最好的情况：`[1,2,...,n]` 全在 → 答案 = `________`
- 最坏的情况：一个都没有 → 答案 = `________`

**这条结论的用处**：任何 **≤0 或 >n** 的数，对答案毫无影响，可以**直接忽略**。这就把「所有数字」缩小到了「值域在 1..n 的数字」。

## 二、思路：把下标当哈希键（原地哈希）

核心一句话：**让数字 `x`（如果 `1 ≤ x ≤ n`）住到下标 `x-1` 的位置上。**

`[3,4,-1,1]`，n=4，手工推一遍（这是本题的灵魂，必须自己走一遍）：

| 轮次 | 现在数组 | 在动谁 | 为什么动 / 动不动 |
|---|---|---|---|
| 初始 | [3, 4, -1, 1] | i=0 | `nums[0]=3`，它该去下标 2（3-1） |
| 第 1 次交换 | [________] | i=0 | `nums[0]=-1`，-1 不在 1..4，停 |
| 往后走 | [________] | i=1 | `nums[1]=4` → 该去下标 3 |
| 交换后 | [________] | i=1 | `nums[1]=1` → 该去下标 0 |
| 交换后 | [________] | i=1 | `nums[1]=-1`，停 |
| i=2,3 | [________] | — | `nums[2]=-1` 不动；`nums[3]=3` 已在正确位置 |

**最后扫描**：从左往右第一个 `nums[i] != i+1` 的位置，答案是 `________`。

### 三个关键细节（这三处写错就死循环或漏解）

1. **为什么要用 `while` 而不是 `if`？**
   因为一次交换换回来的新数字可能还需要再换。但**每个数字最多被放到正确位置一次，总共最多 n 次交换**，所以整体仍是 `O(n)`。

2. **while 的三个条件缺一不可：**
   ```
   while (nums[i] >= 1 && nums[i] <= n && nums[nums[i] - 1] != nums[i])
   ```
   - `nums[i] >= 1 && nums[i] <= n`：不在范围内的不处理（否则下标越界）
   - `nums[nums[i] - 1] != nums[i]`：**目标位置已经是这个数了，就别再换了** —— 这一条是防**死循环**的（想想 `[1,1]`，没有它会怎样：`________`）

3. **为什么交换后 `i` 不往后走？**
   因为换过来的新值可能还没归位，要继续处理同一个 `i`。
