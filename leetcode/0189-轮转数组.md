# LeetCode 189 · 旋转数组（轮转数组）

> 日期：2026-11-14 ｜ 难度：中等 ｜ 标签：数组、数学、双指针
> 思考上限 **25 分钟**，超时看题解，但看完必须关掉题解自己重写。

**题目**：给你一个数组，将数组中的元素向右轮转 `k` 个位置，其中 `k` 是非负数。

```
输入：nums = [1,2,3,4,5,6,7], k = 3
输出：     [5,6,7,1,2,3,4]
解释：向右轮转 1 步 → [7,1,2,3,4,5,6]
     向右轮转 2 步 → [6,7,1,2,3,4,5]
     向右轮转 3 步 → [5,6,7,1,2,3,4]
```

**要求**：原地修改，`O(1)` 额外空间。（先能做出来，再想 O(1)）

---

## 一、思路（先想三种，再动手）

### 解法 A：额外数组（最简单，但空间 O(n)）

思路：新建一个长为 n 的数组，遍历原数组，把 nums[i] 放到新数组的 (i + k) % n 位置，最后再拷回 nums。

- 关键下标换算：新位置 = (i + k) % n
- 时间复杂度：O(n) ｜ 空间复杂度：O(n)

### 解法 B：三次反转（**本题最优解，必须会**）

这是最巧的一个，记住它的**三步**：

1. 反转整个数组：`[1,2,3,4,5,6,7]` → `[________]`
2. 反转前 `k` 个：→ `[________]`
3. 反转后 `n-k` 个：→ `[________]`

做完填这张表（k=3, n=7）：

| 步骤  | 操作区间      | 结果              |
| --- | --------- | --------------- |
| 初始  | —         | [1,2,3,4,5,6,7] |
| 第1步 | 反转 [0, 6] | [7,6,5,4,3,2,1] |
| 第2步 | 反转 [0, 2] | [5,6,7,4,3,2,1] |
| 第3步 | 反转 [3, 6] | [5,6,7,1,2,3,4] |

- 时间复杂度：O(n) ｜ 空间复杂度：O(1)（反转只用两个指针，是 O(1)）

### 解法 C：环状替换（了解即可）

- 一句话思路：从下标 0 出发，把当前元素搬到 (i + k) % n，被挤出来的元素再继续搬到它的 (i + k) % n，像接力传棒一样走下去，直到回到起点；然后换下一个起点（start++）继续，直到 所有 n 个元素都被搬过一遍 。
- 为什么会「回到起点但还没遍历完」？：因为 k 和 n 不互质时，走 n / gcd(k, n) 步就会闭环，闭环后只能覆盖到 n / gcd 个元素，必须再换个起点重新走。→ 用  gcd(k, n) （k 和 n 的最大公约数）来控制循环次数，即外层循环跑 gcd 次（也等价于“统计已移动元素数 count，到 n 就停”）。

## 二、代码（写解法 B）

```java
class Solution {
    public void rotate(int[] nums, int k) {
        int n = nums.length;
        k = k % n;                    // 先取模，防止 k 越界（本题第一坑）
        reverse(nums, 0, n - 1);      // 1. 整体反转
        reverse(nums, 0, k - 1);      // 2. 前 k 个反转
        reverse(nums, k, n - 1);      // 3. 后 n-k 个反转
    }

    // 辅助方法：反转 [left, right] 闭区间
    private void reverse(int[] nums, int left, int right) {
        while (left < right) {
            int tmp = nums[left];
            nums[left] = nums[right];
            nums[right] = tmp;
            left++;
            right--;
        }
    }
}

```

## 三、踩坑记录（**必填**）

- [ ] **`k` 可能大于数组长度！**
  `k = 10, n = 7` 时，实际轮转 3 位。
  所以第一行必须先写：k = k % n;

（这一步忘了，`k=10` 会直接数组越界。这是本题第一大坑。）

- [ ] 三次反转的**第二段和第三段的分界**是哪？
  前 k 个是 [0, k-1]，后 n-k 个是  [k, n-1] 。

- [ ] 反转函数我写成左闭右开还是左闭右闭？我选的是 左闭右闭，
  对应条件是 while (left < right)，指针移动是  left++; right--。

- [ ] 其他卡住的地方：k=0 时 k-1=-1 的情况——其实因为 while (left < right) 天然不成立，所以安全

## 五、最优解 / 换个思路

- 解法 A 明明更简单，为什么题目要求 O(1) 空间？
  → 时间复杂度都是 O(n)，但额外数组要多占一份 O(n) 内存。在实际工程里（例如处理超大数组、嵌入式内存受限场景），原地算法能避免额外内存分配和 GC 压力；这道题就是在考“能不能在受限空间下完成操作”的思维。
- 「三次反转」这个技巧还能用在哪？（提示：**字符串翻转单词顺序**，LeetCode 151）
  → 先整体反转整个字符串，再反转每个单词，就把“倒序”变成了“单词顺序不变、单词内部正序”。本质都是“用多次局部翻转拼出一个循环/重排效果”。
- 如果要求**向左**轮转，三步反转的顺序要不要改？
  → ___三步顺序要改 ：先反转前 k 个 [0, k-1]，再反转后 n-k 个 [k, n-1]， 最后 整体反转。也就是说“整体反转”从第一步挪到第三步。左轮转和右轮转是镜像关系，先处理的段正好反过来。（自己推一下 `[1,2,3,4,5,6,7], k=3` 左轮转应该得到什么）
