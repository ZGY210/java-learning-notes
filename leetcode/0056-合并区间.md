# LeetCode 56 · 合并区间

> 日期：2026-11-11 ｜ 难度：中等 ｜ 标签：数组、排序、贪心
> 思考上限 **25 分钟**，超时就去看题解，但看完必须关掉题解自己重写一遍。

**题目**：给定一组区间 `intervals`，合并所有重叠的区间，返回不相交的区间集合。

示例：

```
输入：[[1,3],[2,6],[8,10],[15,18]]
输出：[[1,6],[8,10],[15,18]]
解释：[1,3] 和 [2,6] 重叠 → 合并为 [1,6]
```

---

## 一、思路

**先别写代码，先用中文把算法说出来。**

1. 第一步必须先做什么？先 排序 。(不排序合并会错：试 [[8,10],[1,3],[2,6]]，从前往后看，[8,10] 和后面的 [1,3] 不重叠，会先把它放进结果，等后面 [1,3]、[2,6] 才重叠，结果就变成 [[8,10],[1,6]]，顺序和正确答案都不对—— 不排序就全靠"后一个的左端点和已合并的区间比"，会出现本该合并的区间被漏掉。)

2. 排序按什么排？按 左端点 升序。（因为"是否重叠"的核心判断是"当前区间的左端点和已有右端点比"，按左端点排好后，每个区间只可能和 它前面最近的那个结果区间 重叠，一遍扫描就能覆盖所有情况。）

3. 遍历的时候，怎么判断「当前区间」和「上一个结果区间」要不要合并？

   - 判断条件：当前左端点  ≤  上一个结果右端点 → 说明重叠
   - 合并后的新右端点取：取 max(前面右端点, 当前右端点) 。因为可能是"区间完全包含"的情况（如 [1,10] 和 [2,3]），如果直接取第二个的右端点 3，就把 10 丢了；取 max 才安全。

4. 输出的结果集为什么用 `List<int[]>` 而不用 `int[][]`？因为合并后 区间数量不确定 （可能变少），而 int[][] 数组长度固定、创建时就要确定大小；List 长度可变，先往里加，最后再转成数组。

---

## 二、复杂度

- 时间复杂度：**O(n log n)**，其中  n 是区间个数
  - 排序 O(n log n)，遍历 O(_n_)
- 空间复杂度：**O(log n)**
  - 除了结果集之外，额外用了 排序的栈开销 （Java 的 Arrays.sort 对对象数组用归并/TimSort，递归栈 O(log n)）

## 三、代码

```java
import java.util.*;

class Solution {
    public int[][] merge(int[][] intervals) {
        if (intervals.length <= 1) return intervals;

        // 1. 按左端点排序
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));

        // 2. 遍历合并
        List<int[]> res = new ArrayList<>();
        for (int[] cur : intervals) {
            // res 为空，或当前区间和上一个结果不重叠 → 直接加进去
            if (res.isEmpty() || cur[0] > res.get(res.size() - 1)[1]) {
                res.add(cur);
            } else {
                // 重叠 → 更新上一个区间的右端点为较大值
                int[] last = res.get(res.size() - 1);
                last[1] = Math.max(last[1], cur[1]);
            }
        }

        // 3. List 转数组返回
        return res.toArray(new int[res.size()][]);
    }
}

```

// 用例 3：[[1,4],[0,4]]                 期望 [[0,4]]      ← 排序后顺序变了

## 五、最优解 / 换个思路

- 有没有不用排序的解法？时间复杂度能更好吗？
  →一般情况下 不能 。合并区间必须知道相对顺序，排序是下限 O(n log n)。但如果区间端点值域很小（比如都在 0~10000 以内），可以用 差分/计数 做：开一个长度 = 最大值 的数组，区间 [l, r] 就在 diff[l]++、diff[r+1]--，然后前缀和扫一遍，前缀和 > 0 的地方就是被覆盖的，连续 > 0 的一段就是一个合并后区间。时间 O(n + V)，V 是值域，属于特殊场景（值小才划算）。
- 这道题和 **LeetCode 57（插入区间）** 的关系是什么？
  → 57 是 56 的"局部版/特例"：56 给一堆乱序区间让全合并；57 给一个 已经有序、且互不重叠 的区间列表，再插入一个新区间，让结果依旧有序不重叠。57 不需要排序，只需从左往右找插入点，扫一遍 O(n) 即可。 56 是"通用合并"，57 是"在有序基础上增一个"。
- 面试官追问：「如果区间数量是 10 万，还能这么做吗？」→ 能 。O(n log n) 在 n = 10 万时 = 约 170 万次比较，完全在可接受范围（Java 里几十毫秒）。内存方面结果集最多 10 万个区间，也 OK。 反倒是"差分计数法"在值域到 10^9 时会直接爆内存 ，这时更应该用排序法。

## 六、30 秒口述版（面试时怎么说）

> 「先按  左端点升序  排序，然后遍历，用一个结果列表存合并后的区间。如果当前区间的  左端点  小于等于结果里最后一个区间的  右端点 ，就说明重叠，把最后一个区间的右端点更新成  两者右端点的较大值（max） 。否则当前区间作为一个新区间加进去。时间 O(n log n) 主要是排序，空间 O(log n) 是排序的栈开销（不计返回值）。」
