## 一、思路

### 我自己先想到的（笨办法）

> ① **第一反应** ：新建一个数组，遍历原数组，把非零元素依次放进去，剩下位置补 0，再把新数组复制回原数组；或者遍历一遍记下所有零的下标，逐个往后挪。
>
> ② **复杂度** ：时间 O(n)， **空间 O(n)** （多开了一个数组）。
>
> ③ **卡在哪 / 为什么不够好** ：题目要求 **原地** 操作（in-place），不能额外开数组；而且"挪元素"的做法会产生大量重复移动。核心问题是—— **我只想着"把零挪走"，没反过来想"把非零留下"** 。

### 更好的做法

> **顿悟点** ：把「把非零元素往前放」想成 **非零往前排，零自然被挤到后面** ——不需要主动去碰任何一个 0。
>
> 用 **快慢双指针** ：
>
> - `slow`：下一个「该放非零元素」的位置；
> - `fast`：负责探路，扫描每个元素。
>
> `fast` 每遇到一个非零，就跟 `slow` 交换（或写入），然后 `slow++`。遍历结束，`slow` 之后的位置自然全是 0。
>
> **一句话** ： **不是"搬运零"，而是"收集非零"；收集完，零就自动留在后面了。**

### 为什么它能成立

> - `slow` 始终指向"已处理区间中第一个空位"，所以 `[0, slow)` 里全是非零，且 **保持原有相对顺序** （因为 fast 是从左到右扫的）。
> - `slow` 永远 **≤ fast** 。两者之间夹着的，恰好就是"已经扫过但还没安置的零"。
> - 交换（而不是覆盖）的好处：交换后，`fast` 位置的旧值被换到 `slow` 处， **零被顺势推到了后面** ，一步同时完成"非零前移"和"零后移"，且 **不丢数据** 。
> - 遍历完，所有非零都在 `[0, slow)`，剩下 `[slow, n)` 自然是 0——因为非零都被搬走了，剩下的只能是零。

## 二、复杂度

| 版本  | 时间   | 空间   |
| --- | ---- | ---- |
| 笨办法 | O(n) | O(n) |
| 更优解 | O(n) | O(1) |

推导过程（不要只写结果）：

- **时间** ：`fast` 从 0 走到 n-1，每个元素 **恰好访问一次** ；遇到非零时做一次交换（常数操作）。总次数 = n 次访问 + 最多 n 次交换 = **O(n)** 。注意不是 O(n²)——因为"找零"是由 fast 顺路完成的，没有对每个元素再套一层循环。
- **空间** ：只用了 `slow`、`fast` 两个下标变量和一个临时变量 `temp`， **与 n 无关** ，是 **常数级** ，即 **O(1)** 。

### 版本二：更优的

```java
class Solution {
    public void moveZeroes(int[] nums) {
        int i=0,j=1;
        while(j<nums.length){
            if(nums[i]!=0){
                i++;
            }
            if(nums[j]!=0){
                nums[i]=nums[j];
                nums[j]=0;
            }
            j++;
        }
    }
}
```

## 四、踩坑

> 这一栏是最值钱的。面试官问「你踩过什么坑」时，答案从这里来。

- [ ] 坑 1：写成了 **`nums[fast] == 0` 才处理** ，结果是 **零被搬到前面、非零反而跑到后面，或者循环里什么都没做** ，原因是 **搞反了判断条件——我们要"收集非零"，所以条件应该判 `nums[fast] != 0`。**
- [ ] 坑 2：写成了 **先 `nums[slow] = nums[fast]` 覆盖，却忘了把原 `nums[fast]` 置 0** ，结果是 **非零元素被复制了一份，原位置的旧值（含零）残留，数组既有多余副本又漏了零** ，原因是 **覆盖是"复制"不是"移动"，数据没有腾挪；要么交换，要么复制完再补零。**
- [ ] 坑 3：写成了 **交换时没让 `slow++`** ，结果是 **后面每个非零都往同一个 `slow` 位置覆盖，最终只剩最后一个非零元素** ，原因是 **`slow` 是"下一个写入位"，写满一个必须推进，忘了自增就一直在原地打转。**
- [ ] 坑 4：写成了 **`for (int i = 0; i < nums.length; i++) { if (nums[i] == 0) { /* 找后面的非零来换 */ } }` 再套一层内层循环找非零 **，结果是 ** 能过用例但复杂度变成 O(n²)，大数据量超时 **，原因是 ** 每个零都重新往后找一遍非零，重复扫描；而快慢指针让 fast 顺路就把这件事做了，是 O(n)。**
