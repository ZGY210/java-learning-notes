# LeetCode 238 · 除自身以外数组的乘积

> 日期：2026-11-14 ｜ 难度：中等 ｜ 标签：数组、前缀积
> 思考上限 **25 分钟**。**要求：不许用除法**，且 `O(1)` 额外空间（返回值不计）。

**题目**：给你一个整数数组 `nums`，返回数组 `answer`，其中 `answer[i]` 等于 `nums` 中除 `nums[i]` 之外其余各元素的乘积。

```
输入：nums = [1,2,3,4]
输出：     [24,12,8,6]
解释：answer[0] = 2*3*4 = 24
     answer[1] = 1*3*4 = 12
     answer[2] = 1*2*4 = 8
     answer[3] = 1*2*3 = 6
```

**为什么不许用除法？** 因为数组里可能有 **0**。想想 `[0,1,2]` 和 `[0,0,3]` ——
用「总乘积 ÷ 自己」会怎样？

总乘积恒为 0，除以任何数（包括 0 之外的）都得不到正确答案；而且一旦 nums[i] 本身是 0，就变成 0 除以 0，直接除零异常。  所以题目禁止除法，本质是要你避开“0 污染全局乘积”这个坑。

---

## 一、思路（三档，从暴力到最优）

### 第一档：暴力（O(n²)）

- 对每个 `i`，再遍历一遍数组把非 `i` 的乘起来
- 复杂度：时间  O(n²)  ｜ 空间  O(1) （不算返回值）
- 面试时说它 = 送分，除非面试官让你从这起步

### 第二档：两个数组（前缀积 + 后缀积，O(n) 空间）

定义两个数组：

- prefix[i] = nums[0] * nums[1] * ... * nums[i-1]（不含 nums[i] 自己）
  prefix[0] = 1（空积是 1，不是 0）
  递推式：prefix[i] = prefix[i-1] * nums[i-1]
- suffix[i] = nums[i+1] * ... * nums[n-1]（同样不含自己）
  suffix[n-1] = 1
  递推式：suffix[i] = suffix[i+1] * nums[i+1]

最后 answer[i] = prefix[i] * suffix[i]

**用 nums = [1,2,3,4] 手填这张表（这是本题的核心，必须自己算一遍）：**

| i   | nums[i] | prefix[i] | suffix[i] | answer[i] |
| --- | ------- | --------- | --------- | --------- |
| 0   | 1       | 1         | 24        | 24        |
| 1   | 2       | 1         | 12        | 12        |
| 2   | 3       | 2         | 4         | 8         |
| 3   | 4       | 6         | 1         | 6         |

### 第三档：只用一个数组（O(1) 额外空间，**最终答案**）

技巧：把 `answer` 数组**先当成 prefix 用一遍**，然后再从右往左用一个变量滚出 suffix，边滚边乘。

1. 第一遍从左往右：`answer[i]` 存 prefix 积
2. 第二遍从右往左：维护一个变量 `right`（初始为  1 ），每步先 answer[i] = answer[i] * right，然后 right = right * nums[i]
- 为什么这样就省掉了 suffix 数组？因为后缀积可以边遍历边算，right 变量在从右往左走的过程中，恰好就是“当前位置右边的所有元素之积”，用完即更新，不需要额外数组存历史。
- 时间  O(n)  ｜ 空间  O(1) （除返回值外）

## 二、代码

```java
class Solution {
    public int[] productExceptSelf(int[] nums) {
        int n = nums.length;
        int[] answer = new int[n];

        // 第一遍：answer[i] = prefix 积（不含自己）
        answer[0] = 1;
        for (int i = 1; i < n; i++) {
            answer[i] = answer[i - 1] * nums[i - 1];
        }

        // 第二遍：从右往左，用 right 滚 suffix 积，边滚边乘
        int right = 1;
        for (int i = n - 1; i >= 0; i--) {
            answer[i] = answer[i] * right;
            right = right * nums[i];
        }

        return answer;
    }
}

```

## 三、踩坑记录（**必填**）

- [ ] **`prefix[0]` 和 `right` 的初始值是 1，不是 0。**
  写成 0 的话，答案全是 0。因为乘法的单位元是 1 （任何数 ×1 = 本身）。

- [ ] 第二遍循环的**起点下标**是 `n-1` 还是 `n-2`？
  n-1 。因为要处理最后一个元素（它的答案 = 左边全部积 × 右边空积 1），从 n-1 开始才能把 right 的初始值 1 正确用上。

- [ ] `answer[i] = answer[i] * right` 和 `right = right * nums[i]` 这两行的**顺序**能不能换？
  不能换顺序 。换了会多乘一个  nums[i] 自己 。我验证的结果：换序后输出变成每个位置乘上了自身，答案全错（如 [1,2,3,4] 会变成 [24,48,72,96] 这种每个都多乘一位）。

## 五、最优解 / 换个思路

- 如果用除法（面试官允许时），要先处理几种情况？
  →0 个 0 ：直接总积 ÷ 自己； 1 个 0 ：只有 0 那个位置答案是总积（其他都是 0）； ≥2 个 0 ：所有位置答案都是 0。仍要小心除零和个位数 0 的特判。
- 「前缀积」这套思路还能解什么题？（提示：**前缀和** LeetCode 560、**最大子数组** 53）
  → LeetCode 560「和为 K 的子数组」 （前缀和 + 哈希）、 LeetCode 53「最大子数组和」 （也可用前缀和思想或多维 DP）；核心都是“用前缀量把区间乘积/和 O(1) 算出来”。
- 这道题和第 3 题（移动零）、第 56 题（合并区间）有什么共同的思维方式？
  → 都是 “用一次或两次遍历、维护一个滚动状态/指针，把需要的中间量就地算出来，避免额外空间” ——也就是典型的 原地操作 + 双指针/滚动变量 思维。

## 六、30 秒口述版

> 「两次遍历。第一次从左往右，把每个位置左边的乘积存进结果数组，起始值 1。
> 第二次从右往左，用一个变量维护右边的乘积，每步先把结果乘上右边积，再更新右边积。
> 这样结果数组被复用了，额外空间是 O(1)。时间 O(n)。」
