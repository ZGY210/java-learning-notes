# 20. 有效的括号

> 难度：简单 ｜ 归属：LeetCode 60 题 · 阶段三（哈希与字符串）#25 ｜ 日期：2026-11-18
> 关键词：**栈**、括号匹配、边界处理

---

## 一、题目（自己用一句话复述）

给定只包含 `(` `)` `{` `}` `[` `]` 的字符串，判断括号是否有效。

有效 = ①左括号必须用同类型右括号闭合 ②闭合顺序正确 ③空字符串算有效。

我的复述：

```
从头扫描字符串，遇到左括号就压栈，遇到右括号就检查栈顶：栈顶是对应的左括号则弹出、继续；不是或栈为空则立即返回 false；扫完后栈必须为空。左括号没用右括号闭合、闭合顺序错、出现多余右括号都无效，空字符串算有效。
```

示例：

- `"()"` → true
- `"()[]{}"` → true
- `"(]"` → false
- `"([)]"` → false  ← 顺序错
- `"{[]}"` → true

---

## 二、思路（为什么是栈）

**核心想法**：遇到左括号就压栈，遇到右括号就看栈顶是不是它的「另一半」。

- 是 → 弹出，继续
- 不是 → 立刻 false
- 栈空了还遇到右括号 → false（右括号多了）
- 全部遍历完栈不空 → false（左括号多了）

**必须回答：为什么用栈而不是用队列？**

填：

```
括号匹配是 后进先出 的嵌套结构：最近出现的左括号必须最先被闭合。栈顶永远是最"迫切"等待匹配的左括号，所以用栈。队列是先进先出，会先检查最早出现的左括号，而它可能被外层包裹、还不到闭合的时候，顺序就乱了。
```

## 三、三种写法（至少写前两种）

### 写法一：Map 存配对 + Deque 当栈（推荐）

```
public boolean isValid(String s) {
    Map<Character, Character> pairs = Map.of(')', '(', ']', '[', '}', '{');
    Deque<Character> stack = new ArrayDeque<>();

    for (char c : s.toCharArray()) {
        if (pairs.containsValue(c)) {       // 左括号
            stack.push(c);
        } else {                            // 右括号
            if (stack.isEmpty() || stack.peek() != pairs.get(c)) {
                return false;
            }
            stack.pop();
        }
    }
    return stack.isEmpty();
}

```

**⚠️ 为什么用 `Deque` 不用 `Stack`？**（11/15 那三道错题里考过）

填：

```
Stack 是 JDK 1.0 的遗留类，继承自 Vector， 每个方法都加了 synchronized ，单线程下白白付出锁开销，性能更差。
Stack 的底层是数组，继承 Vector 后暴露了 get(i)、add(i, e) 这些能任意位置插入删除的 API， 破坏了栈"只能从一端操作"的封装 。
Deque 接口的 push/pop/peek 语义清晰，ArrayDeque 用循环数组实现，性能优于 Stack，是官方推荐做法。
一句话：Java 里要当栈用， 用 Deque + ArrayDeque，不要用 Stack 。
写法二：纯 if-else（不建 Map）
```

### 写法二：纯 if-else 判断（不建 Map，更快）

```java
public boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>(s.length() / 2 + 1);

    for (char c : s.toCharArray()) {
        switch (c) {
            case '(' -> stack.push(')');     // 压入期望的右括号
            case '[' -> stack.push(']');
            case '{' -> stack.push('}');
            default -> {                     // 遇到右括号
                if (stack.isEmpty() || stack.pop() != c) {
                    return false;
                }
            }
        }
    }
    return stack.isEmpty();
}

```

### 写法三（可选）：不用栈，用计数器？想清楚为什么不行

填：

```
计数器只能统计"数量"是否相等， 但无法保证顺序正确 。反例："([)]" —— ( 和 [ 各 1 个、) 和 ] 各 1 个，总数配平，计数器会判 true，但实际是错的（交叉嵌套）。括号匹配要求"最近打开的先闭合"，这是 有序性 要求，必须靠栈的 LIFO 才能记录。只有一种括号时（比如只判断 ()）才可以用计数器。
```

## 四、踩的坑（今天必须至少写 2 条，写真实的）

1. 只配平数量、没配平顺序 ：一开始想用计数器分别统计 ( ) [ ] { } 出现次数，相等就返回 true。结果 "([)]" 这种交叉嵌套判错。
2. 忘了判断栈空 ：遇到右括号直接 stack.peek()/pop()，输入 "]" 时抛 NoSuchElementException，应该先判 stack.isEmpty() 再取栈顶。
3. 结束时忘了检查栈是否为空 ：输入 "(" 时全程不返回 false，最后栈里还剩 (，必须 return stack.isEmpty() 而不是 return true。

**特别注意这三个用例，你代码跑过吗？**

- `"]"` → 应该是 false（第一个就是右括号）
- `"("` → 应该是 false（左括号没闭合）
- `""` → 应该是 true（空串）
