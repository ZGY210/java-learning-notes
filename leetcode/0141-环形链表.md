## 一、思路

### 我自己先想到的（笨办法）

> ① **第一反应** ：开一个 `HashSet<ListNode>`，从头遍历，每到一个节点就查一下是否存过；存过说明绕回来了 → 有环；走到 `null` 都没重复 → 无环。
>
> ② **复杂度** ：时间 O(n)，空间 O(n)。
>
> ③ **卡在哪里** ：能过，但不够好。空间从 O(1) 涨到 O(n)——链表有 10 万个节点就得额外 10 万个引用。面试官会追问："能不能不用额外空间？"

**提示**：最直观的是「用 HashSet 记录访问过的节点」。空间 O(n)。有没有不用额外空间的办法？

### 更好的做法（快慢指针）

> **顿悟点** ：不需要记住"去过哪些节点"，只需要两个 **速度不同** 的指针在跑。
>
> 慢指针每次走 1 步，快指针每次走 2 步。若无环，快指针一定先撞到 `null`；若有环，两只指针都会进环，而快比慢每轮多走 1 步，二者距离每轮缩短 1， **必定在有限步内相遇** 。

**提示**：一个指针每次走 1 步（慢），一个每次走 2 步（快）。如果有环，快的一定会从后面追上慢的；如果没有环，快的会先走到 null。

### 为什么它能成立

> 设进入环后慢指针距快指针（沿前进方向）为 `d`，环长 `c`：
>
> - 每轮快比慢多走 1 步 → 距离 `d → d-1 → d-2 → … → 0`
> - 因为每一步都是整数，且 `d < c`，所以一定会在 ≤ `c` 轮内缩到 0
> - 快指针不会"跳过"慢指针，因为相对速度只有 1

**提示**：快指针每次比慢指针多走 1 步。在环里，两者的距离每轮缩短 1。有环时距离最终会缩到 0（相遇）；无环时快指针先到 null。这就是 Floyd 判圈，也叫「龟兔赛跑」。

## 二、复杂度

| 版本      | 时间   | 空间   |
| ------- | ---- | ---- |
| HashSet | O(n) | O(n) |
| 快慢指针    | O(n) | O(1) |

推导过程（不要只写结果）：

- HashSet：每个节点存一次查一次，O(n) 时间、O(n) 空间
- 快慢指针：O(n) 时间（快指针最多走 n 步）、O(1) 空间（就两个指针）

## 三、代码

### 版本一：HashSet（能过）

```java
class Solution {
    public boolean hasCycle(ListNode head) {
        // 记录访问过的节点，重复出现就是有环
        Set<ListNode> seen = new HashSet<>();
        while (head != null) {
            if (!seen.add(head)) {   // add 返回 false = 之前存过
                return true;
            }
            head = head.next;
        }
        return false;
    }
}

```

### 版本二：快慢指针（最优）

```java
class Solution {
    public boolean hasCycle(ListNode head) {
        // 空链表或单节点不可能有环，直接返回
        if (head == null || head.next == null) {
            return false;
        }
        ListNode slow = head;
        ListNode fast = head;
        // 必须同时判 fast 和 fast.next，否则 fast.next.next 会 NPE
        while (fast != null && fast.next != null) {
            slow = slow.next;          // 慢走 1 步
            fast = fast.next.next;     // 快走 2 步
            if (slow == fast) {        // 相遇即有环
                return true;
            }
        }
        return false;                  // 快指针走到头 → 无环
    }
}

```

## 四、踩坑

> 这一栏是四段里**最值钱**的。

- [x] 坑 1：循环条件只写了 `fast != null`，没写 `fast.next != null` —— `fast.next.next` 会 NPE。
- [x] 坑 2：先移动再判断相遇，还是先判断再移动？顺序不同结果不同，想清楚。
- [x] 坑 3：`head` 为 null 或单节点时要能正确处理。
