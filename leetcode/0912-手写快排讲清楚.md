# 0912. 手写快排的「讲清楚」（LeetCode 912 用）

> LeetCode 912 「排序数组」是让你当场写快排的中等题，面试必考。
> 今天把「你能怎么讲」写成 5 段，然后自己把 partition 在纸上默写一遍。

链接：https://leetcode.cn/problems/sort-an-array/

---

## 一、快排的一句话思想

> 选 pivot，把比它小的放左、大的放右，然后对左右两边**递归**。
> 核心在 partition（分区)，不在 quickSort 本身。

---

## 二、partition 到底在干什么（必须能默画）

> 令 pivot = a[high]，i = low-1（记录比 pivot 小的最右位置）
> 遍历 j 从 low 到 high-1：
>   若 a[j] < pivot：i++，交换 a[i] 和 a[j]
> 最后交换 a[i+1] 和 a[high]，pivot 落位到最终正确位置
> 返回 i+1

画一遍（数组 {3,7,1,9,2,5}，pivot=5）：

```
j  a[j]   是否 < pivot   操作                            数组状态
0  3      是             i=0，交换 a[0]↔a[0]             [3, 7, 1, 9, 2, 5]
1  7      否             跳过                            [3, 7, 1, 9, 2, 5]
2  1      是             i=1，交换 a[1]↔a[2]             [3, 1, 7, 9, 2, 5]
3  9      否             跳过                            [3, 1, 7, 9, 2, 5]
4  2      是             i=2，交换 a[2]↔a[4]             [3, 1, 2, 9, 7, 5]
```

---

## 三、复杂度

- 平均时间：O(n log n)，最坏 O(n²)（每次选到最差 pivot，比如已排序数组）
- 空间（递归栈）：O(log n)
- 稳定性：不稳定（交换可能改变相对顺序）

---

## 四、为什么面试爱考它

- 用到了递归 + 分治，考验你对递归边界的理解
- partition 看似简单但一不留神就写错下标 —— 正好考验细节

## 五、我踩过的坑（写下来）

- [ ] 坑 1：把 i 初始设成 low 而不是 low-1，导致第一个元素总被重复交换
- [ ] 坑 2：递归忘了加终止条件 low >= high，栈溢出
- [ ] 坑 3：把 pivot 放在最左，然后没处理「已排序数组退化成 O(n²)」的场景

---

## 六、怎么避免快排退化（加分题）

> 1. 每次 partition 前，在 `[low, high]` 范围内随机选一个下标，与 `a[high]` 交换后再当基准。这样即使输入数组已有序，也很难每次都取到极值，把最坏情况从"必现"变成"概率极小"。（随机选 pivot）
>
>    
> 2. 取 `a[low]`、`a[mid]`、`a[high]` 三个数的中位数作为 pivot，避免选到最大或最小值。对已排序数组尤其有效。（三数取中做 pivot）
