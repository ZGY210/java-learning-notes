## 一、它是什么

> 三次握手：
>
> 四次挥手：______

**三次握手图**（默画，别抄）：

```
客户端                          服务端
  |------ SYN (seq=__1__) ------>|
  |<--- SYN+ACK (seq=_y_, ack=_x+1_)|
  |------ ACK (ack=__y+1__) ------>|
```

**四次挥手图**（默画）：

```
主动关闭方                      被动关闭方                              
  |------ FIN=1, seq=u -------------->|   FIN_WAIT_1
  |<----- ACK=1, ack=u+1 -------------|   CLOSE_WAIT
  |         （服务器可能还在发数据）    |
  |<----- FIN=1, seq=w, ack=u+1 ------|   LAST_ACK
  |------ ACK=1, ack=w+1 ------------>|   CLOSED
   TIME_WAIT（等 2MSL 后关闭）
```

## 二、它为什么存在（面试必答）

- 为什么握手是三次、不是两次？→ 1.确认双方的收发能力都正常  2.防止历史连接.
- 为什么挥手是四次？→ 因为 TCP 是全双工的，两个方向要**分别**关闭。服务器收到 FIN 后可能还有数据没发完，所以 ACK 和 FIN 不能合并.
- TIME_WAIT 为什么要等 2MSL？→ 1.保证最后的 ACK 能到达  2.让本次连接的残留报文在网络中消亡

## 三、什么场景 / 有什么坑

- 抓包看到大量 TIME_WAIT 说明什么？→ 让本次连接的残留报文在网络中消亡
- SYN 泛洪攻击利用的是哪一步？→ 三次握手的第一步
