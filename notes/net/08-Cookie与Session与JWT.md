# 08 · Cookie、Session、Token、JWT

> 对应《计算机网络面试手册》D8 ｜ 学完填三问。

## 一、横向对比

|         | 存在哪                           | 服务端有状态          | 集群友好           | 能主动失效                  |
| ------- | ----------------------------- | --------------- | -------------- | ---------------------- |
| Cookie  | **浏览器（客户端）**                  | **无状态**         | **友好**         | **不能（需配合服务端）**         |
| Session | **服务端（内存/Redis），ID 存 Cookie** | **有状态**         | **不友好（需共享存储）** | **能（删服务端记录）**          |
| Token   | **客户端（前端存储，随请求带上）**<br></br>  | **无状态（或可配黑名单）** | **友好**         | **不能（除非加黑名单）**         |
| JWT     | | **客户端（三段字符串）**              | **无状态**         | **友好**         | **不能（除非加黑名单/短 token）** |

## 二、JWT 三段（必背）

> JWT =**Header . Payload . Signature** （三段用 `.` 连接）
> Header：**算法类型（alg）+ 令牌类型（typ），Base64URL 编码**
> Payload：**存放声明（用户信息、过期时间等）**（只是 Base64，不加密）
> Signature：**对前两段用密钥做签名，用于防篡改、验真伪**

**关键**：Payload 里**绝对不能放密码/手机号**，因为它只是编码，谁都能解开。

**怎么退出登录？** → **无法直接失效，需靠服务端配合**（JWT 本身无法主动失效，要用 Redis 黑名单或短 token）

## 三、和项目的关系

> 你项目一的登录会用什么方案？→ ______（JWT）
> 为什么不用 Session？→ Session 是服务端有状态，多台服务器集群要共享存储、扩展麻烦；JWT 无状态、客户端自带，天然适合分布式和前后端分离。
