# 04 · TCP 与 UDP

> 对应《计算机网络面试手册》D4 ｜ 学完填三问。

## 一、它是什么

> TCP：**面向连接、可靠、面向字节流的传输层协议** ，通过三次握手建立连接、四次挥手断开连接，保证数据有序、不丢、不重复。
> UDP：**无连接、不可靠、面向报文的传输层协议** ，发之前不用握手，只管把数据包扔出去，不保证对方一定收到。

|       | TCP                      | UDP                  |
| ----- | ------------------------ | -------------------- |
| 面向连接？ | 是，三次握手建连                 | 否，发就走                |
| 可靠？   | 序号 + ACK + 重传 + 校验和，保证送达 | 不保证顺序、不保证到达、丢了就丢了    |
| 传输方式  | 面向字节流，无消息边界              | 面向报文，保留消息边界          |
| 头部开销  | 大，默认 20 字节，选项后更大         | 极小，固定 8 字节           |
| 典型场景  | HTTP/HTTPS、文件传输、邮件、远程登录  | 直播、游戏实时对战、DNS、语音视频通话 |

## 二、它为什么存在 / 怎么选

> 什么场景该用 TCP？→ **要求数据不能丢、顺序不能乱的场景** ：比如网页加载、文件下载、支付接口、邮件发送，宁可慢一点也不能出错。
> 
>
> 什么场景该用 UDP？→**允许少量丢包、但对延迟极其敏感的场景** ：直播、实时游戏对战、DNS 查询、语音视频通话，丢几帧不影响体验，但卡顿延迟会直接毁掉体验。
> 
>
> HTTP/3 为什么改用 UDP？→ 传统 TCP 里，一条连接上只要一个包丢了，后面所有包都得等它重传恢复（队头阻塞）。HTTP/3 在 UDP 之上自己实现了类似 TCP 的可靠机制（QUIC），既保留了 UDP 的低延迟，又能做到 **多路独立流** ——一个流丢包不阻塞其他流，大幅提升弱网下的网页加载速度。

## 三、什么场景 / 有什么坑

> UDP 会粘包吗？→ **不会** 。UDP 是面向报文的，一次 send 对应一次 receive，天然保留消息边界，要么整个包完整收到，要么整个包直接丢，不存在 TCP 那种"字节流合并/拆分"的粘包拆包问题。
