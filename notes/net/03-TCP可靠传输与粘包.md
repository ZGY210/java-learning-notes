# 03 · TCP 可靠传输与粘包

> 对应《计算机网络面试手册》D3 ｜ 学完填三问。

## 一、它是什么

> TCP 靠哪几件事保证可靠？→ **序号、确认（ACK）、超时重传、校验和** 四件套。
>
> **滑串窗口**解决什么问题？→ 解决 **流量控制** ：发送方按接收方通告的窗口（rwnd）调整发送量， **别把接收方缓冲区撑爆** ，同时实现 **连续发送** 而非"发一个等一个 ACK"，提升吞吐。窗口随 ACK 前移。
>
> **粘包 / 拆包**是什么？→ TCP 是 **面向字节流** 、没有消息边界。多个消息被合并成一段收到 = **粘包** ；一个消息被拆成多段收到 = **拆包** 。根因是"一次 write 不等于一次 read"。

## 二、它为什么存在（面试必答）

- 为什么「可靠传输」需要序号 + 确认 + 重传 + 校验和？---->因为四个机制各堵一种漏洞，缺一个就补不全:
- 序号    乱序、重复
- 确认 ACK    让发送方知道送达
- 超时重传    丢包
- 校验和    数据损坏





- 流量控制（rwnd，接收方）和拥塞控制（cwnd，发送方）有什么不同？→ 

  **流量控制 vs 拥塞控制**：
  - 流量控制：**接收方**能力有限，通过窗口字段告诉发送方
  - 拥塞控制：**网络**拥堵，发送方自己猜。四个阶段：慢启动（指数增长）→ 拥塞避免（线性）→ 快重传 → 快恢复。

## 三、什么场景 / 有什么坑

> 三种解决粘包的方式：**定长** / **分隔符** / **长度字段**
> UDP 会不会粘包？→ **不会。** UDP **面向报文** 、保留了消息边界，一次 send 对应一次 receive，要么整个收到要么整个丢，不存在粘/拆。代价是它不保证顺序、不保证到达、不重传——"不粘包"不等于更可靠。
