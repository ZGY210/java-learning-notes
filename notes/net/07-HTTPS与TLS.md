# 07 · HTTPS 与 TLS 握手

> 对应《计算机网络面试手册》D7 ｜ 学完填三问。

## 一、它是什么

> HTTPS = **HTTP + TLS/SSL** （在 HTTP 与 TCP 之间加了一层 TLS 加密层）
> 解决 HTTP 的三大问题： **窃听（机密性） / 篡改（完整性） / 冒充（身份认证）**

**混合加密**：

- 非对称加密（RSA/ECDHE）：慢但安全，用来 协商出会话密钥（交换对称密钥 / 身份认证）
- 对称加密（AES）：快，用来 加密实际传输的应用数据

## 二、TLS 1.2 握手（默画）

```
1. Client Hello：支持的协议版本、密码套件、随机数 random1
2. Server Hello：选定套件、随机数 random2、服务器 证书（含公钥）
3. 客户端校验证书：用 CA 公钥（证书链验证）验签 → 确认身份 → 生成 pre-master（预主密钥），
   用服务器公钥加密后发过去
4. 双方用 random1 + random2 + pre-master 算出 会话密钥（master secret）
5. 之后用 会话密钥（对称加密） 加密通信
```

> TLS 1.3 把握手压到   1   次往返（1-RTT），并废掉了 RSA 密钥交换（改为 ECDHE，实现前向安全）。

## 三、证书链

> 信任链：服务器证书 → 中间 CA → 根 CA（内置在浏览器/操作系统）
> 根证书为什么是信任起点？→ 它是 **自签名证书** ，被操作系统/浏览器预置在受信任列表里，不再向上追溯，成为信任锚点。
> 为什么抓包看不到 HTTPS 内容？→ 应用数据被 **对称密钥加密** ，抓包只能看到密文；密钥由握手协商、只存在于两端，中间人无法解密。
