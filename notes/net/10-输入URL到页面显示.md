# 笔记 · 输入 URL 到页面显示（全链路）

> 对应计算机网络手册 **D10 收官**。这是计网面试出现频率最高的开放题，没有之一。
> 面试官问这一题，考的不是背诵，而是「你能不能把 10 天的知识串成一条线」。

## 一、它是什么

> 一句话说清这条链路上有多少个环节。

浏览器输入 `https://www.example.com/index.html` 回车后，依次发生：

1. **URL 解析** —— 拆出协议 / 域名 / 端口 / 路径 / 查询参数
2. **DNS 解析** —— 域名 → IP（浏览器缓存 → 系统缓存 → hosts → 本地 DNS → 根 → 顶级 → 权威）
3. **建立 TCP 连接** —— 三次握手
4. **TLS 握手**（https 才有）—— 证书校验 + 密钥协商
5. **发送 HTTP 请求** —— 请求行 / 请求头 / 请求体
6. **服务端处理** —— 负载均衡 → 应用服务器 → 数据库 / 缓存
7. **返回 HTTP 响应** —— 状态码 / 响应头 / 响应体
8. **浏览器渲染** —— HTML 解析 → DOM → CSSOM → 渲染树 → 布局 → 绘制
9. **断开连接** —— 四次挥手（或 keep-alive 复用）
10. **缓存** —— 强缓存 / 协商缓存决定要不要重新请求

> 上面这 10 步是骨架。**你要做的是给每一步填上「为什么」和「坑」，而不是抄一遍顺序。**

---

## 二、它为什么存在（每一步解决了什么问题）

> 挑 4 步深挖，其余写一句就够。

### 第 2 步：DNS 为什么要分层（根 → 顶级 → 权威）？

**核心：去中心化 + 可扩展。** 全球域名上亿，不可能一个服务器存全量映射。

### 第 3 步：为什么是三次握手而不是两次？

核心：让双方都确认"自己能收发、对方也能收发"。

### 第 4 步：TLS 为什么要「非对称协商 + 对称传输」两段式？

核心：非对称安全但慢，对称快但怕密钥泄露，各取所长。

### 第 6 步：为什么要在应用服务器前面放负载均衡？

核心：高可用 + 可扩展 + 解耦。

---

## 三、什么场景用它、有什么坑

- 坑 1：**DNS 缓存导致改了解析不生效** ——明明把域名指向换了新 IP，本地访问还是走旧 IP。
- 坑 2：**HTTP/1.1 队头阻塞** ——一个 TCP 连接上，前一个请求没返回，后面的请求全被卡住排队。
- 坑 3：**HTTPS 慢在哪** ——慢在两个地方，不在加密本身：额外一轮握手（RTT）,非对称加解密开销
