# 01 · BigDecimal 为什么不能用来算钱

> 归属 `notes/java-basics/` ｜ 写于 2026-10-14 ｜ 对应黑马 161（BigInteger）、162（BigDecimal）

## 一、它是什么

> 钱这个大小是很重要的,但double在表达小数时会出现无法完全表达小数的情况,数字会出错,钱的数量会不对.
>
> 比如(0.12 + 0.13 = 0.25，(0.12+0.13)==0.25 为 true。而0.1 + 0.2 = 0.30000000000000004)

## 二、它为什么存在（解决了什么问题）

> double在进行计算或者是打印是为什么常常数据对不上? --> 计算机在表达小数时,依然是使用二进制的方法,用二进制对应的权重大小进行计算,这只能表达部分小数
>
> BigDecimal在以字符串传递小数时,为什么可以精确表达小数? --> 因为BigDecimal 内部是「一个 BigInteger(intVal) + 一个 int(scale)」。BigInteger 用 int[] mag 存的是二进制数值.

## 三、什么场景用它、有什么坑

> BigDecimal在需要高精度的计算时,如:金额,财务,支付.
>
> 坑:
>
> 1.用double构造BigDecimal,如:BigDecimal bd = new BigDecimal(double 值);
>
> 2.使用除法时不指定精度,舍入乱选;
