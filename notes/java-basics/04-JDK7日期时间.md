## 一、它是什么

> JDK 7 处理日期时间的 **老三件套** ：`java.util.Date`（一个时间戳）、`java.util.Calendar`（能拆分年/月/日/时/分/秒的日历）、`java.text.SimpleDateFormat`（日期和字符串之间互转的格式化器）。

## 二、它为什么存在（解决了什么问题）

> - **`Date` 的问题** ：它的绝大部分 getter/setter（`getYear()`、`getMonth()` 等）在 JDK 1.1 就被标记 `@Deprecated` 了，因为 **月份从 0 开始、年份从 1900 开始** 这种设计反人类，而且它本身 **不带时区/日历系统** 的概念，国际化处理很别扭。
> - **`Calendar` 的问题** ：作为 Date 的补救方案出现，能按字段取值、能做日期加减（`add`）、能处理闰年和时区。但它 **设计臃肿** （近 100 个方法、大量常量）、 **可变** （改一个实例会影响所有引用它的代码）、 **月份仍从 0 开始** 。
> - **`SimpleDateFormat` 的问题** ：日期和字符串互转必须有它。但它 **不是线程安全的** ，这是最大的雷。

## 三、什么场景用它、有什么坑

> 老项目 / JDK 7 环境里的日期加减、格式化、解析、算两个日期间隔。
>
> 坑:
>
> SimpleDateFormat 线程不安全
>
> 日期计算别自己用毫秒加减
