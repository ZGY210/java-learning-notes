## 一、必答

### 1. 页面置换算法要解决的问题是什么？（一句话）

答：

```
内存（物理帧）不够用、发生缺页时，从当前已装入内存的页面中挑选一个页面换出到磁盘，腾出空闲帧给新页面。
```

### 2. 四种算法分别「换出谁」？各用一句话。

- OPT ：换出 未来最长时间不再被访问 的页面（以后永不访问的优先）。
- FIFO ：换出 最早进入内存 的页面（先进先出）。
- LRU ：换出 最久没有被访问过 的页面（最近最少使用）。
- Clock ：换出 环形缓冲区中下一轮扫描时访问位为 0  的页面（近似 LRU）。

### 3. OPT 为什么无法实现？那它有什么用？

答：

```
需要预先知道 未来完整的页面访问序列 ，而真实程序运行时未来访问无法预知，所以无法实现。作用是作为 理论最优基准（下限） ，衡量其他算法离最优有多远——缺页次数只能接近、不可能低于它。
```

### 4. 什么是 Belady 异常？哪种算法会出现？

答：

```
分配帧数增加时，缺页次数 不降反增 的反常现象。 FIFO  会出现（OPT、LRU 属于栈式算法，不会出现）。
```

### 5. 为什么 LRU 在真实系统里很难做到「精确」？实际怎么近似？

答：

```
精确 LRU 需要每次访问都更新记录（时间戳/链表移动）并支持按“最久未用”排序，硬件上对每次内存访问都做这种维护 开销太大 。实际用 近似算法 ：Clock（时钟）算法，靠硬件 访问位（reference bit）  加指针扫描，用访问位为 1 就置 0 跳过、为 0 就换出的方式，低成本逼近 LRU。
```

## 三、必答概念

### 7. 「局部性原理」是什么？它和页面置换算法是什么关系？

答：

```
程序在一段时间内的访问集中在 少数页面 上——时间局部性（刚用过的还会用）+ 空间局部性（用到的紧邻的也会用）。正因为访问有局部性， 保留“最近用过/常驻”的页面、换出很少用的页面才有效 ，这才使 FIFO/LRU/Clock 等置换策略能减少缺页。没有局部性，任何置换算法都无从预测、失效。
```

### 8. 抖动（Thrashing）是什么？它和「内存给得太少」什么关系？发生时 CPU 利用率会怎样？

答：

```
进程 大部分时间都在换页 （缺页—换入—立刻又缺页—换出），真正干活的极少。根因是 分配给进程的物理帧太少 ，装不下它的工作集，导致刚换进来的页面马上又被换出，恶性循环。发生时  CPU 利用率会急剧下降 （甚至接近 0），因为 CPU 一直在等磁盘 I/O。
```

## 四、自测（闭卷）

1. FIFO 的 Belady 异常举一个例子。
    访问序列 1 2 3 4 1 2 5 1 2 3 4 5：3 帧时 FIFO 缺页 9 次，4 帧时缺页 10 次—— 帧数增加，缺页反而更多 。
3. LRU 用「哈希表 + 双向链表」实现，两个结构各负责什么？
    哈希表 ：key → 链表节点，实现 O(1) 定位某个 key 是否在缓存、拿到对应节点；
    双向链表 ：维护访问顺序（头=最近使用、尾=最久未用），实现 O(1) 把节点移到头部、O(1) 删除尾节点。两者配合，get/put 都是 O(1)。
5. Clock 算法比 LRU 省在哪一步？
    省掉了 每次访问都要精确更新“最久未用”顺序 这一步（LRU 每次命中都要把节点移到链表头/更新时间戳）。Clock 只把该页 访问位置为 1 ，换出时靠指针转圈扫描、遇到 0 就换出、遇到 1 就清零，用一次扫描近似替代精确排序，硬件成本低得多。
7. 工作集（Working Set）是什么？

```
进程在某个时间窗口（如最近 Δ 时间内的访问） 实际需要常驻内存的页面集合 。分配帧数应至少覆盖工作集，否则会抖动。
```

## 五、和 Java 的关系

### 9. JVM 分代回收的假设是什么？它和「局部性原理」是不是同一个思想？

答：

```
分代回收的假设是： 大多数对象朝生夕死 （弱分代假说）、少量对象长期存活；且对象间引用集中在同代（强分代假说）。本质是 局部性原理的延伸 ——把“生命周期短的对象集中在新生代、频繁小范围回收（Minor GC），生命周期长的在老年代、偶尔回收（Major GC）”，和局部性“访问集中在少数区域”的思想一致，都是 把有限处理资源放在活跃区域上 。
```

## 六、一句话总结

```
页面置换算法是在内存不够时“换出谁”的策略： OPT 理论最优但不可实现，FIFO 简单却会 Belady 异常，LRU 精而贵、Clock 用访问位廉价近似 LRU ；它们都建立在一个前提上—— 程序有局部性 。
```
