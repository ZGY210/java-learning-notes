## 一、必答（每题至少 3 行，答不出就空着，别抄）

### 1. 进程之间为什么不能直接读写对方的内存？

答：

```
因为操作系统给每个进程分配了 独立的虚拟地址空间 ，进程 A 里地址 0x1000 和进程 B 里地址 0x1000 通过各自的页表映射到不同的物理内存。一个进程看不到另一个进程的页表，也就拿不到对方的物理地址。此外，进程之间还有 内存保护 （页表的用户/内核权限位），就算知道对方物理地址也读不到，越界访问会触发段错误（SIGSEGV）。这正是进程隔离的基石——保证一个进程崩溃或恶意操作不会破坏别人。
```

### 2. 六种 IPC 方式，各用一句话说清它是什么（不许只写名字）

1. 管道 pipe ：内核里的一块环形缓冲区，只能用于 有亲缘关系 （父子/兄弟）的进程，单向、字节流、无消息边界。
2. 命名管道 FIFO ：在文件系统里有路径名（如 /tmp/myfifo）的管道， 无亲缘关系的进程也能通过打开同一路径通信 ，仍是单向字节流。
3. 消息队列 ：内核维护的链表，以“消息”为单位收发（有类型和长度边界），可按类型选择性读取，与进程是否存活无关。
4. 共享内存 ：把同一块物理内存映射到多个进程的地址空间，双方直接读写同一份内存，是 IPC 里最快的。
5. 信号量 ：一个内核维护的计数器，用于 同步和互斥 （P/V 操作），本身不传数据，只协调“能不能进”
6. Socket ：通过 IP + 端口寻址的通信端点， 唯一能跨机器 的方式，支持 TCP（可靠字节流）/UDP（数据报）。

### 3. 为什么共享内存「最快」？那它的代价是什么？

答：

```
最快是因为它 没有数据拷贝 。管道、消息队列、Socket 都要经历“用户态 → 内核缓冲区 → 用户态”至少两次拷贝，共享内存直接 mmap 到各自地址空间，读写就是普通内存访问，一次拷贝都省了。
代价是 它本身不带任何同步机制 ，两个进程同时写同一块内存就会数据竞争，必须额外配信号量/互斥锁来做互斥；而且共享内存的生命周期独立于进程，进程异常退出时共享段可能残留（需手动 shmctl 删除或设 IPC_RMID），容易泄漏。
```

### 4. mutex 和 semaphore 最本质的区别是什么？

答：

```
mutex 是“锁”，semaphore 是“计数器” 。
mutex 表达的是 所有权 ：加锁的线程才能解锁，取值只有 0/1（锁定/未锁定），本质是“某个资源当前被谁独占”。
semaphore 表达的是 可用资源数量 ：初值可以是 N，P 减 1、V 加 1，谁都能 P/V，不关心“谁持有”，本质是“还剩多少份资源可用”。
```

### 5. Java 的 `synchronized` 和 `wait/notify`，在操作系统层面分别对应什么？

答：

```
synchronized 对应 互斥锁 mutex ：进入同步块要获得 monitor 的锁，对应 OS 的加锁/解锁；竞争失败线程被阻塞挂起。
wait/notify 对应 条件变量（condition variable） ：wait() 让线程释放锁并挂到条件队列上等待（对应 pthread_cond_wait），notify/notifyAll 唤醒等待者（对应 pthread_cond_signal/broadcast）。
二者是配合关系：一个 mutex 可以挂多个条件变量（JVM 里每个对象一个 monitor，wait set 就是它的条件队列）。这是典型的“互斥锁 + 条件变量”模型。
```

## 三、自测（闭卷，3 题，不许翻上面）

1. 进程间通信为什么不能直接读对方变量？
   因为每个进程有独立虚拟地址空间，页表不同，同一虚拟地址映射到不同物理页；且有内存保护，跨进程读写会触发段错误。
2. 六种 IPC 里哪一种能跨机器？
   只有  Socket 。其余五种（管道、FIFO、消息队列、共享内存、信号量）都限定在同一台机器内核里。
3. 一个信号量初值 5，被 P 了 7 次会发生什么？
   前 5 次 P 后值变 0，第 6、7 次 P 时值已为 0，调用线程会被 阻塞挂起 ，加入该信号量的等待队列，直到有其他线程/进程执行 V 操作释放资源才能被唤醒。如果只 P 不 V，程序永久挂起（死锁）。

## 四、今天必须记住的一句话

> 用自己的话写一句：

```
进程之间内存互相看不见，所以通信要么靠内核中转（管道/消息队列/Socket，要拷贝），要么靠映射同一块物理内存（共享内存，零拷贝但必须自己加同步）；而同步的两种基本武器就是互斥锁（管独占）和信号量（管计数）。
```
