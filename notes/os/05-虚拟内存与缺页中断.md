## 一、必答

### 1. 虚拟内存是什么？它解决了哪两个问题？

答：

```
虚拟内存：给每个进程一套 独立的、连续的虚拟地址空间 ，由 CPU 的 MMU + 页表在运行时把虚拟地址翻译成物理地址。
解决两个问题：
内存隔离/保护  —— 每个进程有独立地址空间，看不到也改不了别的进程内存。
内存不够用 + 地址空间不连续  —— 程序不用全装进物理内存，按页调入即可；物理内存碎片也能被页表打散映射。
```

### 2. 分页和分段，用一句话分别说清「分的是什么」。

答：

```
分页：分的是「物理内存」 ，按固定大小（如 4KB）机械切块，不看内容。
分段：分的是「程序的逻辑」 ，按代码段、数据段、栈段这种功能单位切，大小不等。
```

### 3. 页大小一般是多少？为什么是这个数量级（不是 1KB，也不是 1MB）？

答：

```
一般  4KB （部分系统 2MB 大页）。
为什么不是 1KB 或 1MB：
太小（1KB）→ 页数暴涨，页表巨大、TLB 命中率低、缺页次数多，开销太大。
太大（1MB）→ 内部碎片严重（一个进程最后没用满的页浪费大）、页表项也少但每次缺页要搬 1MB，I/O 代价高。
4KB 是「页表大小、TLB 覆盖范围、碎片浪费」三者的平衡点。
```

### 4. 为什么要多级页表？单级页表的问题是什么？

答：

```
单级页表问题： 整个页表必须常驻内存且连续 。32 位、4KB 页 → 一个进程页表要 2^20 项 × 4B ≈  4MB ，每个进程都占 4MB，几百个进程就爆了。
多级页表：把页表本身再分页， 只加载用到的部分 ，没用的二级页表可以放磁盘/根本不分配，大幅省内存。（代价是多一次内存访问，所以才有 TLB。）
```

### 5. TLB 是什么？命中 / 未命中分别走什么路径？

答：

```
TLB =  快表 ，是 MMU 里的页表项缓存，存最近用过的虚拟页号 → 物理页框号。
命中 ：直接用 TLB 里的物理地址 → 一次内存访问完成。
未命中 ：走完整 多级页表 逐级查（多级就多几次内存访问），查到的项回填 TLB，再访问数据。
```

## 二、缺页中断（必须按顺序写出流程）

### 6. 一次缺页中断，从「CPU 访问到不在内存的地址」到「指令重新执行」，写完整流程（至少 5 步）。

答：

```
CPU 访问虚拟地址，MMU 查页表，发现 页表项无效位 （页不在内存）→ 触发 缺页异常 。
硬件跳转到缺页异常处理程序，把控制权交给 OS。
OS 检查地址是否合法（越界/无权限 → 段错误，直接杀进程）。
合法则在物理内存找 空闲页框 （没有就跑页面置换算法，选一个换出）。
从磁盘（swap 区或文件） 把所需页读入 该页框。
更新页表 （填入页框号、置有效位），刷新 TLB。
返回， 重新执行导致缺页的那条指令 。
```

### 7. 缺页中断是「异常」还是「中断」？为什么它不算出错？

答：

```
是 异常（exception） ，具体说是 故障（fault） 这一类，不是外部硬件中断。
不算出错，因为它是「 正常的、预期内的 」处理流程——页只是暂时不在内存，把它调进来、 重新执行指令就能正常完成 。它不是程序逻辑错误，也不是硬件故障。
```

### 8. 「缺页」和「内存不足」是一回事吗？举两个「缺页但内存还很宽裕」的例子。

答：

```
不是一回事。缺页只表示「这一页当前不在物理内存」，和物理内存总量无关。
例子：
程序刚启动 ：操作系统按需加载，第一次访问代码/数据段必然缺页，但内存空得很。
文件映射 mmap / 访问大文件 ：按需从磁盘读入，内存充裕也会频繁缺页。
```

## 三、自测（闭卷）

1. 一次缺页大概比一次正常内存访问慢几个数量级？
    约  10^5 ~ 10^6 倍 （内存几十纳秒，磁盘毫秒级，一般是 6 个数量级 / 十万倍左右）。答「5~6 个数量级」即可。
3. 页表项里通常存哪些信息？
    物理页框号（PPN）、 有效位/存在位 、 访问位 （用于置换）、 脏位 （修改过没）、 保护位 （读写执行权限）、有时还有 cache 相关位。
5. 写时复制（Copy-on-Write）触发的是缺页吗？
    是 。写时拷贝时该页被标记为 只读 ，第一次写触发 写保护异常（也属于缺页类异常） ，OS 复制一份再改。这是缺页异常的一种应用。
7. 32 位进程为什么最多只能有 4GB 虚拟地址空间？

```
32 位地址总线能表示 2^32 个地址，2^32 B =  4GB 。地址空间上限由地址位宽决定，跟物理内存多大无关。
```

## 四、和 Java 的关系（必答）

### 9. `-Xmx8g` 到底承诺了什么？是立刻占 8G 物理内存吗？

答：

```
-Xmx8g 承诺的是  JVM 堆可用地址空间的上限是 8G ，不是立刻占 8G 物理内存。
它是 虚拟内存 的预留（向 OS 申请地址空间），实际物理内存 按需 commit 、由加载/使用才逐步占用。所以设 8G 不代表开机就吃 8G 物理内存；反过来设了 8G 也可能因为实际物理内存不够而触发 swap 甚至 OOM。
```

### 10. `-Xss1m` 影响什么？它和一个程序「最多能起多少线程」有什么关系？

答：

```
影响 每个线程的栈大小 （这里 1MB/线程，包括虚拟机栈 + 本地方法栈）。
关系：每个线程要占一块栈空间， 栈越大，能起的线程越少 ；栈越小，能起的线程越多（但太小可能 StackOverflow）。所以「最多线程数」很大程度上受 线程栈大小 × 线程数 ≤ 可分配虚拟地址空间 限制。
```

## 五、一句话总结

```
虚拟内存用页表把每个进程的独立地址空间映射到物理内存，让 内存隔离、按需加载、超量使用 成为可能；分页负责物理分配，TLB 负责加速，缺页异常负责把不在内存的页调进来。
```
