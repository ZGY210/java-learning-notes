## 一、必答

### 1. 为什么要分用户态和内核态？如果不分会发生什么？

答：

```
因为要 保护关键资源 + 做隔离 。如果所有代码都能直接操作硬件、修改内核数据结构、访问任意进程内存，那么一个普通程序（甚至一个 bug 或恶意程序）就能随意破坏系统、篡改别的进程数据、让整台机器崩溃或数据泄露。分态后， 关键操作必须经过内核的受控入口（系统调用） ，由内核检查权限后才执行，保证安全与稳定。
```

### 2. 两个态的本质区别是什么？（提示：不是「模式开关」，是特权级）

答：

```
本质是  CPU 特权级不同 （x86 上是 Ring 0 与 Ring 3），不是简单的“模式开关”。

内核态（Ring 0）：可执行 特权指令 （改页表、关中断、直接访问 I/O 端口、操作硬件）；
用户态（Ring 3）： 只能执行非特权指令 ，访问受硬件限制，碰特权指令会触发异常陷入内核。
```

### 3. 一次系统调用，从用户代码到内核再返回，写完整 4 步。

答：

```
用户程序 正常执行到系统调用点（如 read），把 系统调用号 和参数放进约定寄存器；
执行 陷入指令 （syscall/int 0x80），CPU  由用户态切换到内核态 ，跳到内核的系统调用入口（查系统调用表定位处理函数）；
内核执行 对应服务例程（如真正去读磁盘/网卡），必要时阻塞或调度；
执行完 返回用户态 ，系统调用返回值（或错误码）放回寄存器，用户程序从陷入指令的 下一条指令 继续执行。
```

### 4. 从用户态掉进内核态，一共几种途径？各举一个例子。

答：

```
系统调用（主动陷入） ：程序调用 read()、fork()；
中断（异步，外部触发） ：时钟中断、网卡收到数据包引发的中断；
异常（同步，指令执行出错触发） ：缺页异常、除零异常、非法指令。
```

### 5. 为什么「态切换」很贵？贵在哪三件事上？

答：

```
保存与恢复现场 ：保存用户态寄存器、程序计数器、栈指针，返回时恢复；
切换栈 ：用户栈 ↔ 内核栈切换，并可能刷新 TLB / 缓存，产生缓存失效；
流水线与 CPU 状态打乱 ：陷入/返回是控制流剧变，会打断流水线、清空部分预取，开销按微秒级计。
```

## 二、必答对比

### 6. 「函数调用」和「系统调用」差在哪？（至少说 3 点）

| 维度   | 函数调用           | 系统调用               |
| ---- | -------------- | ------------------ |
| 运行态  | 同一态内（用户态调用户态）  | **跨态** ，用户态 → 内核态  |
| 开销   | 很小，只压栈跳转       | 大，切态 + 保存现场 + 可能调度 |
| 能做的事 | 只能做用户态允许的事     | 可执行特权操作、访问硬件       |
| 入口   | 直接 `call` 目标地址 | 通过陷入指令进内核固定入口      |
| 权限检查 | 无              | 内核会校验参数与权限         |

### 7. 「系统调用」和「上下文切换」哪个更贵？为什么？

答：

```
上下文切换更贵。  系统调用只是 同进程内用户态↔内核态 切换，进程地址空间基本不变；上下文切换是 从一个进程/线程换到另一个 ，除了切态，还要保存/恢复整套 CPU 上下文、 切换页表（换地址空间）、刷新 TLB、切换栈 ，开销明显更大。（特例：只要系统调用里发生阻塞调度，就会叠加一次上下文切换，此时等于两者都付。）
```

## 三、动手（真敲一次，把输出贴在下面）

### 8. 在你的机器上验证「Java 一次 read 就是一次系统调用」：

先想清楚方案（提示：读 1 字节 vs 读 1MB，计时对比），把你打算怎么做写下来：

```
准备一个较大的文件（如 100MB）；
方案 A：用 无缓冲 的 FileInputStream.read()  逐字节 读（每次 read 就是一次系统调用），计时；
方案 B：用 带缓冲 的 BufferedInputStream（默认 8KB 缓冲，一次系统调用读 8KB），同样读完，计时；
对比两者耗时，并用 strace -c（Linux）/ Process Monitor（Windows）观察实际系统调用次数差异。
```

实际跑出来的数字：

| 方式              | 耗时        | 系统调用次数（约） |
| --------------- | --------- | --------- |
| 逐字节 read(100MB) | ~ 数秒～十几秒  | 1 亿次      |
| 8KB 缓冲读(100MB)  | ~ 几十～几百毫秒 | ~1.3 万次   |

你怎么解释这个差距：

```
每次 read 都是一次 用户态→内核态的态切换 + 陷入 + 返回 ，单次虽小但 高频累积 就成了大头。缓冲流把“1 亿次系统调用”压成“1.3 万次”，每次多读的数据几乎不额外增加成本，于是总耗时骤降。 瓶颈不是磁盘带宽，而是系统调用的次数 × 每次切态开销。
```

## 四、自测（闭卷）

1. Ring 0 和 Ring 3 是什么？
    x86 的  CPU 特权级 （共 4 级 Ring 0~3）。Ring 0 是 内核态 ，权限最高，可执行特权指令；Ring 3 是 用户态 ，权限最低，运行普通应用。数字越小权限越大。
3. `read()` 属于哪种「陷入」？
    属于 系统调用（主动陷入） ——程序主动请求内核服务。
5. 缺页、除零、时钟中断、系统调用，哪些是程序主动的？
    程序主动 ：系统调用（主动请求）；
    被动 ：缺页异常、除零异常（指令执行中出错触发）、时钟中断（外部硬件异步触发）。
7. 为什么说「用户态不能直接读网卡数据」？

```
网卡属于 硬件 I/O 设备 ，读它需要执行 特权指令 并访问受保护的 I/O 端口/内存映射区，Ring 3 无权执行，会触发保护异常。必须由内核驱动读入内核缓冲区，再通过系统调用（如 recv）拷给用户态。
```

## 五、和 Java 的关系（必答）

### 9. 为什么 Java 读文件「必须用缓冲流」？用今天的知识回答。

答：

```
因为 FileInputStream.read() 这类 无缓冲 调用，每读一点点就触发一次 read  系统调用 ，而系统调用要切态、保存现场、切换栈，单次很贵；高频调用会被 态切换开销 拖慢。BufferedInputStream 在内核与用户之间加了一层用户态缓冲区， 一次系统调用读一大块（默认 8KB）进来，后续从内存里取字节 ，把系统调用次数减少几个数量级，才快。
```

### 10. `System.out.println` 为什么在高频循环里很慢？

答：

```
它默认 PrintStream 会 自动刷新（autoFlush）  并且底层写的是 文件描述符/标准输出 ，每次 println 都可能 触发一次 write 系统调用（甚至多次）+ 大量字符串格式化开销 + 可能加锁同步 。循环里调百万次 = 百万次切态 + 格式化 + 同步，自然极慢。所以高并发日志要 缓冲 + 批量刷 + 异步 。
```

## 六、一句话总结

```
用户态/内核态本质是 CPU 特权级的分权：普通代码在 Ring 3 受限运行，需要碰硬件、改关键数据结构时，必须通过系统调用（或中断、异常）陷入 Ring 0 由内核代办；每次切态都要保存现场、换栈、洗流水线，代价不菲——所以性能优化的一个核心就是“减少系统调用次数”，这正是缓冲流的由来。
```
