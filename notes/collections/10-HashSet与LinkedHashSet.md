## 一、它是什么（一句话定义 + 底层是什么）

> HashSet 底层是 **HashMap** ，它本质是「只用 key 的 Map」——所有元素作为 key 存进去，value 统一是一个假的 `PRESENT` 常量对象。
>
> 为什么说它「其实是个只有 key 的 Map」：`add` 直接委托给 `map.put`，返回值判断的是 put 的 **旧 value 是否为 null** ，为 null 说明是新 key，添加成功。

补充要回答的三个点：

1. 为什么 HashSet 的 `add` 平均是 O(1)？它走了哪几步？
    hashCode() 拿到哈希值；
    HashMap 内部扰动：h ^ (h >>> 16)，让高位也参与运算；
    hash & (n - 1) 算出桶下标（n 是容量，2 的幂，等价于取模但更快）；
    桶内用 equals 逐个比较；
    没找到相等元素 → 放入，返回 true；找到了 → 放弃，返回 false。
    每步都是常数时间，所以平均 O(1)。
3. HashSet 允不允许 `null`？能放几个？为什么？
    允许 null 吗？ 允许，且 只能放 1 个 。null 的哈希固定为 0，落进 0 号桶，第二次 add 时 equals 判定已存在。
5. HashSet 的遍历顺序由什么决定？
    由 hash 值决定的桶位置 决定，从 0 号桶依次扫到 n-1 号桶。既不是插入顺序，也不是大小顺序。

## 二、为什么需要它（没有它会怎样）

> 提示：讲清楚「用 List 做去重」有多难受，才能说明 HashSet 存在的价值。

我要自己写出来的：

- 用 `List.contains()` 去重是 O(?) 的，数据量到 10 万会怎样？
    每个新元素都要和列表里所有已有元素比一遍，n 个元素整体 O(n²)。
    数据量到 10 万会怎样 ：10 万 × 10 万 ÷ 2 ≈ 50 亿次比较 ，耗时可达数十秒甚至超时，完全不可用。而 HashSet 是 10 万次 O(1) 操作，毫秒级完成。
- HashSet 的去重为什么能做到平均 O(1)？
    不遍历所有元素，而是先算「位置」（桶下标），只跟同一个桶里的少数元素比较。 用空间换掉了线性搜索。
- 什么时候该用 `LinkedHashSet` 而不是 `HashSet`？（一句话讲清业务场景）
    一句话： 当业务既要去重、又要保留「第一次出现/插入」的顺序时 。典型如「最近浏览记录去重」「用户操作流水去重」「搜索结果去重且保持相关度顺序」。

## 三、坑（这一节最重要，写不出坑说明还没真懂）

按下面 5 个坑逐条填，每条都要写「现象 → 原因 → 怎么避免」：

| #   | 坑                                  | 现象                                  | 原因                                                | 怎么避免                                                    |
| --- | ---------------------------------- |:----------------------------------- | ------------------------------------------------- | ------------------------------------------------------- |
| 1   | 只重写 `equals` 不重写 `hashCode`        | 两个内容相同的对象都留在 Set 里，size 变 2         | 哈希值不同 → 落入不同桶 → 永远不会调用 equals 比较                  | **必须同时重写** ；用 IDE 生成或 `Objects.hash` + `Objects.equals` |
| 2   | 以为 HashSet 有序（1,2,3 加进去出来也是 1,2,3） | 换成 100,2,55 后顺序突然变成 2,100,55        | 小整数 hash 值恰好等于自身，桶下标正好升序，是 **巧合** ；一旦超过容量或哈希值变大就乱 | 记住遍历序 = 桶序 ≠ 插入序；要顺序就换 `LinkedHashSet`                  |
| 3   | 往 Set 放可变对象，放进去又改字段                | `set.contains(s)` 返回 false，明明对象还在里面 | 修改字段改变了 hashCode → 对象仍躺在旧桶，但按新哈希去别的桶找，找不到         | 放进 Set 的对象 **字段应设为 final** ；确需修改则先 remove、改完再 add       |
| 4   | 遍历 Set 的同时 `remove`                | 抛 `ConcurrentModificationException` | 迭代器的 modCount 与集合实际修改次数对不上                        | 用 `Iterator.remove()`，或 `removeIf()`，或先收集到临时集合再删        |
| 5   | 用 `HashSet` 存需要保序的数据（如最近浏览记录）      | 展示顺序每次刷新都不一样，用户看到混乱                 | 遍历顺序由 hash 桶决定，与插入时间无关                            | 保序场景一律用 `LinkedHashSet`                                 |

> 第 1 条是面试原题：「两个对象 equals 相等，hashCode 一定相等吗？反过来呢？」
>
>     equals 相等 ⇒ hashCode 一定相等 ：这是 Java 契约的强制要求。如果违反，HashSet/HashMap 必然出错（相等对象进不了同一个桶）。
>     hashCode 相等 ⇏ equals 相等 ：哈希会冲突，不同对象完全可能算出同一个值。此时它们同桶，靠 equals 分辨。
>     一句话： hashCode 是粗筛，equals 是精判。
>
> 第 3 条值得动手验证：`Student s = new Student("张三"); set.add(s); s.name = "李四"; set.contains(s)` 返回什么？
>
>     add 时按 "张三" 算出哈希落在桶 A；改名为 "李四" 后 hashCode 变了，contains 按新哈希去桶 B 找，桶 A 里那个对象还在，但已经「找不回来」了。 它变成了一个无法访问、也无法删除的幽灵元素 。

## 四、HashSet / LinkedHashSet / TreeSet 三者对比（自己画表）

|                        | HashSet                  | LinkedHashSet                 | TreeSet                          |
| ---------------------- | ------------------------ | ----------------------------- | -------------------------------- |
| **底层结构**               | HashMap（数组 + 链表 + 红黑树）   | LinkedHashMap（HashMap + 双向链表） | TreeMap（红黑树）                     |
| **是否有序**               | 无序                       | 有序                            | 有序                               |
| **顺序由什么决定**            | hash 值决定的桶位置             | **插入顺序** （双向链表串起来）            | 元素大小 / 比较器                       |
| **允许 null 吗**          | 允许 1 个                   | 允许 1 个                        | **不允许** （比较时 NPE，除非自定义比较器处理）     |
| **add / contains 复杂度** | 平均 O(1)                  | 平均 O(1)（略慢，要维护链表）             | O(log n)                         |
| **元素必须实现什么**           | 重写 `hashCode` + `equals` | 同 HashSet                     | 实现 `Comparable` 或传入 `Comparator` |
| **典型场景**               | 快速去重、判断存在性               | 去重 + 保序（浏览记录、操作流水）            | 去重 + 排序（排行榜、区间查询）                |
