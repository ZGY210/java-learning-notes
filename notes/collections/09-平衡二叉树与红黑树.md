# 笔记 · 平衡二叉树与红黑树

> 对应黑马 **194 平衡二叉树旋转机制** + **195 红黑树**。
> 三问骨架。这是 HashMap 源码（红黑树树化）的前置，也是面试里「树」这条线的终点。

## 一、它是什么

### 1. AVL 的平衡因子

> 平衡因子 = 左子树高度 - 右子树高度。AVL 要求任意节点 |平衡因子| ≤ 1。
>
> （补充一句写代码时会用到的：配合 `height` 的 AVL 约定，空节点高度 -1，叶子节点高度 0，所以平衡因子的取值范围是 -1、0、1 三个值。）

### 2. 四种旋转场景（每种一句话 + 一个小图）

| 场景     | 怎么转        | 图（用括号表示）                                     |
| ------ | ---------- | -------------------------------------------- |
| LL（左左） | 右旋一次       | 3(2(1),_) → 2(1,3)                           |
| RR（右右） | 左旋一次       | 1(_,2(_,3)) → 2(1,3)                         |
| LR（左右） | 先左旋左孩子，再右旋 | 3(1(_,2),_) →[左旋1] 3(2(1,_),_) →[右旋3] 2(1,3) |
| RL（右左） | 先右旋右孩子，再左旋 | 1(_,3(2,_)) →[右旋3] 1(_,2(_,3)) →[左旋1] 2(1,3) |

### 3. 红黑树 5 条性质（必背，一字不差）

1. 每个节点要么是红色，要么是黑色
2. 根节点是黑色
3. 叶子节点（NIL / null）是黑色
4. 红色节点的两个孩子都是黑色（**不能有两个连续的红**）
5. 从任一节点到其所有后代叶子，经过的黑色节点数目相同（**黑高相等**）

## 二、它为什么存在（面试分界线）

### 1. BST 为什么需要平衡？退化后复杂度变成多少？

> 顺序插入 1,2,3,4,5 会退化成一条链，本质是链表，查找、插入、删除全部变成 O(n)；平衡后（树高 O(log n)）这些操作恢复到 O(log n)。这就是 AVL 要「旋转」、红黑树要「变色 + 旋转」的全部动机。

### 2. AVL 和红黑树都是平衡 BST，为什么 HashMap / TreeMap 选红黑树而不是 AVL？

> - AVL 追求 **绝对平衡** （高度差 ≤ 1），树更矮，查找更快，但维护代价高——插入/删除后常常要一路旋转到根。
> - 红黑树放宽到 **黑高平衡** ，高度上限约 2log(n+1)，比 AVL 稍高，但插入删除的旋转次数是常数级的（最多 3 次旋转）。
> - 实际场景增删和查找同样频繁，TreeMap 和 HashMap 树化都选了综合成本更低的红黑树。

### 3. 红黑树为什么有「红色节点不能连续」这条规则？

> 如果没有这条，树可能退化成「黑节点串着一串红节点」的不平衡结构。这条 + 黑高相等，共同保证树的高度最多 2log(n+1)，查找稳定 O(log n)。

## 三、什么场景 / 有什么坑

### 我今天踩的坑（写真实过程）

- **坑 1：** 在 `isBalanced` 里，我把 `height()` 返回的 `-1` 当成“错误信号”来判断（写成 `leftHeight == -1 || rightHeight == -1 → false`），结果连只有一个孩子的节点都被判成不平衡。原因是 `-1` 在这套约定里是 **空树的合法高度** ，不是异常码；只有在“边求高度边判平衡”的 O(n) 写法里，`-1` 才被重新征用为“已失衡”标记。两种语义不能混用。
- **坑 2：** `isBalanced` 的 `else` 块漏了递归返回语句，`if` 之后直接结束，编译不过（IDE 打了红波浪线）。补上 `return isBalanced(node.left) && isBalanced(node.right);` 才行—— **当前节点平衡不代表整棵树平衡** 。

### 必答追问

- HashMap 什么时候「树化」？（链表长度 ≥ 8 且数组长度 ≥ 64）
    只满足长度 ≥ 8 但数组还没扩容到 64 时，优先 resize() 扩容而不是树化——因为扩容后会重新散列，链表大概率被拆短。
- 树化之后还会「退化回链表」吗？（长度 ≤ 6 时退化成链表，避免反复横跳）
    会。删除时节点数 ≤ 6 就退化成链表。8 和 6 之间留了缓冲，避免在临界值附近反复树化/退化造成抖动。
- 为什么 TreeMap 底层用红黑树而 HashMap 平时用链表？（有序 vs 哈希，场景不同）
    TreeMap 要 有序 （按 key 排序、支持范围查询、firstKey/lastKey），必须用平衡 BST；HashMap 只需要 按哈希快速定位 ，同桶冲突量小时链表更快更省内存，只有冲突严重时才需要树化兜底。
