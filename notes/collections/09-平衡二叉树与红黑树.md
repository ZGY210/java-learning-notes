## 一、它是什么

### 1. AVL 的平衡因子

> 平衡因子 = 左子树高度 − 右子树高度。AVL 要求任意节点 |平衡因子| ≤ 1。

### 2. 四种旋转场景（每种一句话 + 一个小图）

| 场景 | 怎么转 | 图（用括号表示） |
|---|---|---|
| LL（左左） | 右旋一次 | |

| LR（左右） | 先左旋左孩子，再右旋 | |
| RL（右左） | 先右旋右孩子，再左旋 | |

### 3. 红黑树 5 条性质（必背，一字不差）

1. 每个节点要么是红色，要么是黑色
2. 根节点是黑色
3. 叶子节点（NIL / null）是黑色
4. 红色节点的两个孩子都是黑色（**不能有两个连续的红**）
5. 从任一节点到其所有后代叶子，经过的黑色节点数目相同（**黑高相等**）

## 二、它为什么存在（面试分界线）

### 1. BST 为什么需要平衡？退化后复杂度变成多少？

> 提示：顺序插入 1,2,3,4,5 → 一条链，查找 O(n)。平衡后 O(log n)。

### 2. AVL 和红黑树都是平衡 BST，为什么 HashMap / TreeMap 选红黑树而不是 AVL？

> 关键：AVL 追求「绝对平衡」（高度差 ≤ 1），**查找更快但旋转更多**；
> 红黑树放宽到「黑高平衡」，**插入删除的旋转更少**。
> TreeMap 增删频繁，所以选红黑树。HashMap 树化同理。

### 3. 红黑树为什么有「红色节点不能连续」这条规则？

> 提示：如果没有这条，树可能退化成「黑节点串着一串红节点」的不平衡结构。这条 + 黑高相等，共同保证树的高度最多 2log(n+1)，查找稳定 O(log n)。
