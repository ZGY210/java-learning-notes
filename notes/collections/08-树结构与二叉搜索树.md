# 笔记 · 树结构与二叉搜索树

> 对应黑马 **193 数据结构（二叉树、二叉查找树、平衡二叉树）**。
> 三问骨架。树是后面 TreeMap、红黑树、HashMap 源码的地基。

## 一、它是什么

### 三种树一句话 + 区别表

| 树          | 一句话               | 特点                  |
| ---------- | ----------------- | ------------------- |
| 二叉树        | 每个节点最多两个子节点       | 对节点值没有约束            |
| 二叉查找树（BST） | 左小右大              | 左子树所有值 < 根 < 右子树所有值 |
| 平衡二叉树（AVL） | BST + 左右子树高度差 ≤ 1 | 防止退化成链表             |

### 三个术语

- **深度** = 从根到该节点的边数
- **高度** = 从该节点到最深叶子的边数
- **中序遍历** = 左 → 根 → 右

## 二、它为什么存在（面试分界线）

### 1. 为什么 BST 的中序遍历天然升序？

> BST 的定义是「左子树所有值 < 根 < 右子树所有值」。中序遍历的顺序是「左 → 根 → 右」：
>
> - 先输出左子树（全部比根小）
> - 再输出根
> - 最后输出右子树（全部比根大）
>
> 这个顺序 **恰好等于数值递增顺序** 。而且这个性质对每个子树递归成立，所以整棵树走完就是严格升序。
>
> **延伸** ：这也是「验证合法 BST」常用中序遍历判断是否递增的原因，比逐节点比上下界更直观。

### 2. BST 最坏情况是什么？为什么需要平衡二叉树？

> 按 `1,2,3,4,5` 有序插入，BST 会退化成 **一条只有右孩子的链表** （斜树）。
>
> - 树高 = n，查找/插入/删除全部退化为 **O(n)** ，跟链表没区别，BST 的意义就没了。
> - **AVL 树** 通过旋转，强制任意节点左右子树高度差 ≤ 1，把树高锁在 **O(log n)** ，查找稳定 O(log n)。
> - 代价：每次插入/删除可能触发旋转， **写操作变慢、实现变复杂** ，换来查找稳定。
>
> **一句话** ：BST 快的前提是「树是矮胖的」，而有序数据会把它喂成「高瘦」的，所以需要平衡策略兜底。

### 3. 为什么 `TreeMap` 和 `HashMap` 都跟树有关？

> |             | 数据结构                           | 用树解决什么                                                   |
> | ----------- | ------------------------------ | -------------------------------------------------------- |
> | **TreeMap** | 底层 **红黑树** （一种自平衡 BST）         | 天然支持 **按 key 有序** 遍历、`firstKey`/`floorKey`/范围查询 `subMap` |
> | **HashMap** | 数组 + 链表， **链表长度 ≥ 8 时树化** 成红黑树 | 防止哈希冲突严重时链表退化成 O(n) 查找，树化后单桶查找 O(log n)                  |

## 三、什么场景 / 有什么坑

### 我今天踩的坑（写真实过程）

- **坑 1：把 `insert` 的方法体直接粘进了 `contains` 的字面壳里** 。  
  表现：`boolean` 方法里写了 `return new Node(val);`，还有 `node.left = insert(...)`，编译报「不兼容的类型」和「找不到符号 node」。  
  根因：以为三个方法结构一样，直接复制。实际 **contains 返回 boolean、不需要接住递归返回值、null 时返回 false 不是建节点** 。  
  下次怎么防： **写方法前先回答三问** ——返回类型是什么？`node` 从哪来？递归结果要不要接住？
- **坑 2：`inOrder` 写成了「根 → 左」，且辅助方法返回 String** 。  
  表现：`private String inOrder(Node node, StringBuilder sb)`，里面 `return "";`，还先 `sb.append(node.val)` 再递归左边。  
  根因：① 既然传了 StringBuilder，结果都在 sb 里，方法该是 `void`；② 中序必须先左后根，appending 位置写前面就是前序。  
  下次怎么防： **先写遍历顺序（左、根、右），再往三个位置填 append** 。
- **坑 3（概念坑）：深度 vs 高度 vs 节点数，容易混** 。  
  这题里单节点树「深度 1、节点数 1」碰巧相等，容易蒙对；但 `[1,2,3]` 深度 2、节点数 3，立刻暴露。  
  区分： **深度＝从根往下数（到边数），高度＝从自己往下数到最深叶子，节点数＝数个数** 。

### 必答追问

- 二叉树、BST、AVL、红黑树四者是什么关系？（逐层加约束）
    二叉树 ：每个节点最多两个孩子，无值约束。
    BST ：有序，中序升序，但可能退化成链表。
    AVL ：BST + 严格平衡（高度差 ≤ 1），查找最稳 O(log n)，写操作旋转频繁。
    红黑树 ：BST + 弱平衡（红黑规则保证最长路径 ≤ 最短路径 2 倍），插入删除更省调整，Java 的 TreeMap/HashMap 用它。
- BST 的查找复杂度是多少？最好 / 最坏分别是多少？
    最好 / 平均 ：树是平衡的，高度 O(log n)， O(log n) 。
    最坏 ：有序插入退化成链表，高度 n， O(n) 。
- 递归遍历二叉树的空间复杂度是多少？（提示：栈深度 = 树高）
    O(h)，h 是树高 。递归不额外开数组，但 递归调用栈 的深度等于树高：
      平衡树 h = O(log n) → 空间 O(log n)
      退化成链 h = n → 空间 O(n)（最坏）
