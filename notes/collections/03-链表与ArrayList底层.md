# 笔记 · 链表与 ArrayList 底层

> 对应黑马 **188 数据结构（栈、队列、数组、链表）**。
> 三问骨架，答不出来就回去看那一段。

## 一、它是什么

### 四种数据结构一句话

| 结构  | 一句话              | 典型 Java 类              |
| --- | ---------------- | ---------------------- |
| 数组  | 连续内存、按下标 O(1) 访问 | `ArrayList` 底层、`int[]` |
| 链表  | 节点 + 指针，内存不连续    | `LinkedList` 底层        |
| 栈   | 后进先出（LIFO）       | `ArrayDeque` 当栈用       |
| 队列  | 先进先出（FIFO）       | `ArrayDeque` 当队列用      |

### 单链表 vs 双向链表

> 单链表每个节点只有 `next`；`LinkedList` 用的是双向链表，多一个 `prev`。
>
> - **换来什么** ：① 能反向遍历，不用额外栈；② 删节点时不必知道前驱 —— 拿到节点引用就能自己找到 `prev`，直接 `node.prev.next = node.next` 断链；③ `LinkedList` 靠这个实现 `Deque` 的两端操作（`addFirst`/`peekLast` 都是 O(1)）。
> - **代价** ：每个节点多一个引用字段（64 位 JVM 指针压缩下约 4~8 字节），内存开销更大；每次插入删除要维护两个指针，出错点多；但 **不省时间** ，定位依然要遍历。

## 二、它为什么存在（面试分界线）

### 1. 既然有数组了，为什么还要链表？

> 数组在中间插入/删除，必须把后面所有元素整体后移/前移（`System.arraycopy`），代价 O(n)，而且扩容时要申请更大空间并整块拷贝。链表插入/删除只改几个指针， **已知位置时是 O(1)** ，不需要连续内存，容量不受限。所以「频繁在中间增删、数据量大、不要求随机访问」的场景用链表；「频繁按下标查、整体遍历」用数组。

### 2. `ArrayList` 和 `LinkedList` 到底怎么选？（面试必问，答案要具体）

| 操作               | ArrayList | LinkedList | 为什么                                                               |
| ---------------- | --------- | ---------- | ----------------------------------------------------------------- |
| 按下标随机访问 `get(i)` | O(1)      | O(n)       | 数组有下标偏移公式 `a + i*size`；链表要从头走 i 步（底层还做了二分：i 在前半段从头走、后半段从尾走）       |
| 尾部插入 `add(e)`    | O(1) 均摊   | O(1)       | 数组直接放 `elementData[size++]`，只有扩容那次是 O(n)，均摊摊销掉；链表维持尾指针 `last` 直接挂 |
| 中间插入 `add(i, e)` | O(n)      | O(n)       | 数组要 `arraycopy` 后移；链表虽只改指针，但 **找位置本身** 要走 i 步，一样 O(n)             |
| 中间删除 `remove(i)` | O(n)      | O(n)       | 同上：数组前移后续元素，链表先遍历定位再断链                                            |
| 遍历               | O(n)，快    | O(n)，慢     | 数组连续内存、缓存命中率高；链表节点散落堆上，指针跳转导致大量缓存缺失                               |

### 3. 「LinkedList 增删一定比 ArrayList 快」这句话对不对？

> 不对。这句话偷换了前提。链表增删 O(1) 成立的前提是「 **已经拿到那个节点** 」。但通过下标 `add(i, e)` / `remove(i)` 操作时，先要 **遍历找到第 i 个位置** ，这步是 O(n)；而数组的 `arraycopy` 是连续内存的批量搬移，底层走 native，实际常数很小。加上链表内存不连续、缓存命中率低、每个节点有对象头开销和指针维护， **在中低规模数据下，ArrayList 的中间增删实测往往还更快** 。正确说法是：已知位置（迭代器位置、头尾）时链表才有优势。

## 三、什么场景 / 有什么坑

### 我今天踩的坑（写真实过程）

- **坑 1：插入顺序写反，链断在半路。** 写 `add(index, e)` 时我最初先写了 `prev.next = newNode;`，再写 `newNode.next = prev.next;`。结果 `newNode.next` 拿到的是 **已经被改过的** `prev.next`，也就是 newNode 自己，后继节点整段丢失，`toString` 只打出一个元素。改回先接好 `newNode.next = prev.next`、再接 `prev.next = newNode` 才通。本质和反转链表「先记 next 再掉头」是同一个坑。
- **坑 2：`remove` 没单独处理头节点。** 一开始统一用 `prev.next = prev.next.next`，`index == 0` 时 `prev` 没有前驱会空指针，得先判 `if (index == 0) head = head.next;`。
- **坑 3：`get`/`remove` 的越界判断写成了 `<=`。** 自查第 10 条抛异常用例抓出来的，`get(index)` 必须 `index >= size` 就抛。

### 必答追问

- 手写链表时，`add(int index, E e)` 的 index 合法范围为什么是 `0 <= index <= size`（含 size），而 `get` 是 `0 <= index < size`（不含 size）？
    因为 `add` 是「插入」，可以插在最后一个元素之后，即 index 等于当前长度时表示尾插（插完 size 变 size+1），所以上限能取到 `size`；而 `get` 是「读取已有元素」，合法下标最大只能是 `size - 1`，取 `size` 就越界了。同理 `remove` 与 `get` 一致，上限是 `size - 1`。
- 反转链表时，为什么必须先记 `next` 再改 `cur.next`？
    因为节点的后继只能通过 `cur.next` 读到。一旦执行 `cur.next = prev`，原来指向后面的指针就被覆盖了，后半段链表再也找不到入口（除非另存过引用），程序只能拿到反转了的前半截。所以先把旧后继存到 `next`，掉头后还能靠它继续往后走。
- `ArrayDeque` 为什么比 `LinkedList` 更适合当栈和队列？
    ① 结构：`ArrayDeque` 底层是 **循环数组** （`head`/`tail` 两个下标），内存连续，缓存友好；`LinkedList` 每个元素都是一个 Node 对象，还要维护 prev/next 两个指针，内存开销和缓存缺失都更重。② 速度：两端操作都是 O(1) 且常数极小、无对象分配；`LinkedList` 每次入队都要 `new Node`，GC 压力大。③ 稳定性：`ArrayDeque` 只需在扩容时整块复制，遍历不会因指针链而慢。所以 JDK 官方注释直接写明「作为栈使用时，比 `Stack` 快；作为队列时，比 `LinkedList` 快」，`ArrayDeque` 还不允许 null，能当元素不存在来判断边界。
