# 笔记 · 泛型与通配符

> 对应黑马 **191 泛型类、泛型方法、泛型接口**（192 通配符见下一课）。
> 三问骨架。泛型是「编译期检查 + 运行期擦除」，这两个词要能脱口而出。

## 一、它是什么

> **一句话：** 泛型 = **参数化类型** （把「类型」当作参数来用，让类、方法、接口在 **编译期** 就知道要操作什么类型，而不是依赖运行期强转）。

**三类泛型各举一个例子：**

| 类型   | 语法                        | 例子                                                                             |
| ---- | ------------------------- | ------------------------------------------------------------------------------ |
| 泛型类  | `class Box<T>`            | Box<String> s = new Box<>(); s.put("abc");                                     |
| 泛型方法 | `<T> T method(T t)`       | `public static <T> List<T> arrayToList(T[] arr)`；`<T> T id(T t) { return t; }` |
| 泛型接口 | `interface Comparator<T>` | `Comparator<String> c = (a, b) -> a.compareTo(b);`（`List.sort(c)`）             |

## 二、它为什么存在（面试分界线）

### 1. 没有泛型之前，Java 集合是怎么用的？有什么问题？

> - **必须强转** ，而且每次 `get` 都要写一次。
> - **类型错误全部推迟到运行期** ，编译器拦不住，线上才炸。

### 2. 泛型解决什么问题？代价是什么？

> 好处：编译期类型检查、免强转、代码更安全。
> 代价（关键）：**类型擦除** —— 泛型信息只在编译期存在，运行期 `Box<String>` 和 `Box<Integer>` 是同一个 class。所以「泛型数组不能 new」「不能 instanceof T」这些限制都源于此。

### 3. 类型擦除是什么？（用自己的话写，这是今天的核心）

编译器在把 `.java` 编译成 `.class` 时，会把所有的泛型类型参数 **去掉** ，替换成它的上界（没写 `extends` 就替换成 `Object`），再在需要的地方自动插入 `checkcast` 强转。结果就是：运行期的 `JVM` 根本不知道 `Box` 里装的是什么类型，`Box<String>` 和 `Box<Integer>` 共用同一份字节码——这就是今天 `sameRuntimeClass()` 返回 `true` 的原因。

补充验证方式：`s.getClass().getName()` 输出 `demo.GenericPractice\$Box`，名字里没有 `String` 也没有 `Integer`。

## 三、什么场景 / 有什么坑

### 我今天踩的坑（写真实过程）

- **坑 1** ：`arrayToList` 写完后一排波浪线，我以为循环逻辑写错了，反复改 `for`——结果真正原因是文件头缺 `import java.util.List;` 和 `import java.util.ArrayList;`。教训： **红色是编译错误、黄色才可能是建议** ，先看提示不要瞎猜。
- **坑 2（可补）** ：顺手想用 `Arrays.asList(arr)` 返回，试了 `add` 直接抛 `UnsupportedOperationException`——它是定长视图，必须 `new ArrayList<>(Arrays.asList(arr))` 包一层。
- **坑 3（可补）** ：`Box<Integer>` 里存 `null` 后直接 `int x = box.get();`，拆箱时抛 `NullPointerException`。

### 必答追问

- 为什么 `List<String>` 和 `List<Integer>` 在运行期是同一个类？
    因为泛型类型参数在编译后被擦除，字节码里只剩 List。getClass() 拿到的都是同一个 java.util.ArrayList（或 List 的实现）的 Class 实例，== 比较为 true。
- 为什么不能 `new T()`？（运行期 T 已经被擦成 Object，不知道具体类型）\
    擦除后 T 变成 Object（或上界），编译器和 JVM 都无法知道要 new 哪个具体类的构造器——new Object() 显然不是你要的。正确做法：传入 Class<T> clazz，再 clazz.getDeclaredConstructor().newInstance()；或传入工厂 Supplier<T>。
- 为什么不能 `instanceof T`？（同上，运行期没有 T 这个信息）
    instanceof 是运行期指令，需要一个真实的 Class 对象；而 T 在运行期已不存在（只剩 Object），x instanceof Object 恒为 true，毫无意义。同理 instanceof List<String> 也不合法，只能写 instanceof List（原始类型）或 instanceof List<?>。
- 泛型方法声明里的 `<T>` 写在哪？和泛型类的 `<T>` 有什么区别？
|        | 泛型类 `<T>`                         | 泛型方法 `<T>`                                                      |
| ------ | --------------------------------- | --------------------------------------------------------------- |
| 位置     | 写在 **类名后** ：`class Box<T>`        | 写在 **修饰符与返回类型之间** ：`public static <T> List<T> arrayToList(...)` |
| 作用域    | 整个类（含字段、方法），但 **静态方法不能用** 类上的 `T` | 仅限该方法内部（含返回类型、形参、方法体）                                           |
| 是否同名同源 | 类上的 `T` 与方法是两码事                   | 方法上重新声明的 `T` 是 **独立的类型参数** ，可遮蔽类上的 `T`                          |
