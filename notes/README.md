# notes/ —— 笔记目录

> 笔记不是摘抄，是**用自己的话把原理写一遍**。判断标准只有一个：**合上源码和视频，你能不能把它讲出来。**

---

## 一、目录约定（一个模块一个子目录）

```
notes/
├── java-basics/      # 面向对象、String、异常、IO、泛型、反射
├── collections/      # 集合框架（P1 第 1 个模块）
├── concurrency/      # 多线程与 JUC
├── jvm/              # JVM 内存、GC、类加载、调优工具
├── net/              # 网络编程、TCP/HTTP
├── mysql/            # 索引、事务、MVCC、锁
├── spring/           # IoC / AOP / MVC / MyBatis / Spring Boot
├── 待补-知识漏洞.md    # ⭐ 最重要的一个文件，见下
└── README.md
```

## 二、文件命名

```
<两位序号>-<知识点>.md        例：01-B+树.md、09-MVCC.md
```

序号让目录自带顺序，`09-MVCC.md` 排在 `01-B+树.md` 后面，按顺序读就是一条学习路径。

## 三、每篇笔记用这个骨架（三问内核）

**这是全文最重要的部分。** 面试的分界线就在这里：只会背「是什么」的人，二面必挂。

```markdown
# 09 - MVCC

## 1. 它是什么
（一句话。写不出来说明没懂）

## 2. 它为什么存在？（解决了什么问题）
（面试分界线。没有它之前是什么样？带来什么代价？
  例：MVCC 解决「读写互相阻塞」——没有它时，读要加锁、写要加锁，
  并发度极低；有了它，读不加锁也能读到一致快照，代价是 undo log 膨胀和版本链遍历）

## 3. 什么场景用 / 有什么坑
（结合你踩过的坑写。你实测过的报错原文 > 书上抄的结论）

## 4. 我怎么验证过（可选但强烈建议）
（贴命令、贴输出、贴数据。面试官问「你做过吗」时，这就是答案）
```

## 四、⭐ `待补-知识漏洞.md`

**这个文件比任何一篇漂亮笔记都值钱。**

每周复盘时，把「闭卷答不出来的点」写进去，一行一条，按优先级排序：

```markdown
| 漏洞 | 发现日期 | 优先级 | 状态 |
| --- | --- | --- | --- |
| `modCount` 为什么用 `int` 而不是 `long` | 2026-10-14 | 中 | 待补 |
| CHM 的 `size()` 为什么不精确 | 2026-10-20 | 高 | 待补 |
```

**为什么重要**：人的本能是反复复习已经会的东西（舒服），逃避不会的东西（难受）。这个文件把「不会的东西」显式化，让你没得逃避。考前一周只看这一页。

## 五、两条铁律

1. **复习 ≠ 重看。** 重看视频和重读笔记的效率极低（熟悉感会被误认为掌握）。有效的是**主动回忆**：合上资料，白纸写出来 / 讲给空气听 / 重新敲一遍代码。
2. **整理笔记的时间不要超过总学习时间的 10%。** 超过 20% 就是用「整理笔记」逃避真正的难点。如果一小时里 40 分钟在排版，停下来。
